## 1. 接口决定

- **一次建出 users/roots/entries**：`roots.owner_id → users(id)` 与 `entries(root_id,parent_id) → entries(root_id,id)` 只能用外键表达，而外键要求被引用表存在；因此迁移 0002 同时建三张表。`users` 只有 §7.2 的四个字段（`login` 唯一、`password_hash NOT NULL`——不存在无密码账号、`status` 取值集合留给 S042），账号的 typed API 与初始化流程仍属 S042，本卡不建。
- **身份用 16 字节 BLOB**，不用十六进制文本，避免同一身份两种字节表示。为此在 `crates/domain/src/ids.rs` 追加 `UserId`（`users.id`、`roots.owner_id`），与既有身份同构；不在 server-store 另造 id 表示。
- **owner scope 是参数，不是约定**：每个读写函数都带 `UserId`；不属于该 owner 的 Root/条目返回 `OutOfScope` 或 `None`，不区分“不存在”与“别人的”。写 Root 时先查 `users` 给出 `UnknownOwner`（外键是兜底）。
- **活跃同父名称唯一用两个部分唯一索引**：`(root_id,parent_id,name_key)` 表达平台等价（`name_key` 由调用方按 design §7.2 派生，本层不小写、不归一化），`(root_id,parent_id,name)` 兜住“名字完全一样却给了不同键”的调用方不一致。软删除即释放名称。写冲突按 SQLite 报错文本里的列名映射成 `DuplicateName`/`DuplicateId`，不猜默认值。
- **父子同 Root**：复合外键之外，写接口先给出精确的 `CrossRootParent`；外键本身也被测试（绕过 Rust 直接写 SQL 仍失败）。
- **目录环只在移动时检查**：新建条目的 id 尚未存在，祖先链不可能包含它。检查用递归 CTE 从目标父项向上走，`UNION` 去重因此坏数据里的既有环也会终止；自己当父项同样拒绝。
- **删除不级联**：本卡只写单条 `deleted_at`，并拒绝删除仍有活跃子项的目录（design §7.4“目录删除检查整个子树”的第一半）；子树删除与回收站属 S039。
- **读写分别接事务与连接**：写接口收 `&mut Transaction`（与检查同一持锁事务，无检查竞态），只读接口收 `&mut SqliteConnection`，GET 不必抢写锁。`db::Database::{pool,begin_write}` 的可见性保持 S026 契约不变——本卡靠“提供类型化接口”而不是收紧可见性来约束网络层，残留风险见 §4。
- **名称写库前用 `crates/fs-common::name::validate_name` 校验**（保留名/尾部点空格/非法字符/长度），`name_key` 为空拒绝。
- **health 只取 `healthy`/`unavailable`**：两值都能对回 design（挂载、身份、权限失败即 Root 不可用，不推导删除）；更细的健康原因属 S044。
- `entries.content_version_id` 暂只有长度与“目录无内容版本”约束，指向 `versions` 的外键要到 S028 建表后才能加（SQLite 追加外键需重建表）。

## 4. 限制

- 路径重叠（父子目录、别名、bind 挂载）不在本层判定：`absolute_path` 只做形式检查与全库唯一，重叠检查归 S032 的平台重叠接口与 S044 的注册流程。
- `name_key` 的正确性依赖调用方（S065 的平台等价适配器）：本层能拒绝“键相同”“名字完全相同”，但无法识别“名字不同、键也不同、实际在目标文件系统上等价”的调用方错误。
- `entries.content_version_id` 尚无外键；S028 建 `versions` 表时需要决定是否重建 `entries` 加外键。
- `users`/`sessions` 的读写接口、密码初始化、health 细分原因、Root 注册的挂载准入与路径重叠都留给 S042/S043/S044；`RootHealth` 只有两值，S044 若需要更细状态需追加迁移。
- `db::Database::{pool,begin_write}` 仍是公开接口：“网络代码不能随意 raw SQL”靠本卡提供的类型化接口与代码评审约束，未在 Rust 可见性上强制；S041 组装服务端时可评估是否收紧。
- 目录删除只拒绝非空目录，不做子树软删除；btrfs 上的真实数据未涉及（纯 SQLite 层）。
