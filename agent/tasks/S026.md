## 1. 接口决定

- **库种类标识用 SQLite 原生 `PRAGMA application_id`**，服务端取值 `0x56534E31`（ASCII `VSN1`），不新造 sidecar 文件或种类表。客户端库的标识留给 `crates/client-store` 自己的卡定义；本卡只在测试里用任意异值（`0x434C4E54`），不提前占用客户端的编号。
- **种类门禁**：等于服务端标识放行；`0` 且 `sqlite_master` 里没有任何对象（新文件或空库）允许被初始化为服务端库；`0` 但非空、或任何其它标识一律 `DbError::ForeignDatabase`。不是 SQLite 文件（`SQLITE_NOTADB`，错误码 26）报 `DbError::NotADatabase`。
- **拒绝前不碰对方文件**：探测走独立的只读探测连接（不 `create_if_missing`、不设 `journal_mode`/外键）。因此把客户端库误传给服务端时，`application_id`、`user_version` 与表结构原样保留，不会被改成 WAL（测试断言这三点）。
- **schema 版本用 `PRAGMA user_version`**，目标值由内嵌迁移的最大版本号计算（`target_schema_version()`，当前 `1`），不手写常量，避免“迁移文件加了但常量忘了改”。迁移记账仍由 SQLx 的 `_sqlx_migrations` 承担；版本门禁取 `user_version` 与 `_sqlx_migrations` 最大版本的**较大者**——迁移已提交、标记未写之间中断的库只有记账记得新版本，两个来源都看才拒绝得掉。
- **迁移前一致性备份**用 `VACUUM INTO`（读事务快照，包含 `-wal` 里已提交的数据）再做 `PRAGMA quick_check` 自检；路径 `<库路径>.pre-migration-v<from>-to-v<to>.bak`，同名已存在则保留不覆盖。只在“确实有待执行迁移且库非空”时执行，空库迁移不产生备份。
- **迁移失败不自动 down、也不自动恢复备份**：返回 `Migration { backup, source }` 且不给出可写句柄；库停在最后一个成功迁移（SQLx 把每条迁移与记账放在同一事务，单条失败整体回滚）。回退按 design §19.3 走整套备份恢复。
- **WAL 与外键是每条连接的默认项**（`SqliteConnectOptions`），不是某个调用点临时打开；打开后读回实际 `journal_mode`，不是 `wal` 就 `WalUnavailable` 拒绝启动（覆盖 SMB/NFS/只读存储）。
- **短事务接口**是 `Database::begin_write()` → `BEGIN IMMEDIATE`（先拿写锁，避免“读事务升级写锁”的 `SQLITE_BUSY`），等锁上限 10 s，池上限 4（只服务并发读）。事务里只允许数据库语句：文件系统 I/O 与 SQLite 不是一个事务（design §6）。
- **依赖**：`sqlx 0.8.6`（`runtime-tokio` + `sqlite`（bundled）+ `migrate` + `macros`），dev 依赖 `tokio`（`macros`/`rt-multi-thread`）。`sqlx::migrate!` 编译期内嵌 `migrations/`，不需要运行时目录、`DATABASE_URL` 或 `SQLX_OFFLINE`；bundled SQLite 与 devShell CLI 的版本事实记在 `docs/environment.md` §19。
- **workspace**：`crates/server-store` 加入 `members` 与 `default-members`（无平台 API，任何宿主目标都能编译与测试，便携检查与 CI 覆盖它），理由写在根 `Cargo.toml` 注释。

## 4. 限制

- 只覆盖 schema 版本 1。S027 起追加迁移才会真正走“多版本升级”；本轮用测试内的合成迁移集（同一条 `open` 路径）验证了升级、备份、单条失败回滚、半完成库与旧二进制拒绝。
- 备份留在数据库同目录且不自动清理（每次失败尝试可能留一个 `.bak`）；轮转与清理属于备份/运维卡。
- 未设置 `synchronous`、页大小等调优（design：SQLite 也保留 CoW，先基准测试再决定）。
- WAL 校验只证明当前文件系统能进入 WAL；真实 SMB/NFS 上的拒绝未实测（代码路径相同，但没有该环境的运行证据）。
- `crates/server-store` 的 `entries.rs`/`versions.rs`/`operations.rs`/`changes.rs` 未创建（按 design §5.4 分卡）；§7.2 的业务表未建。
- 连接池上限 4 与 `busy_timeout` 10 s 是工程取值，未做并发压测；S106/S107 调优时以实测替换。
