## 1. 结果

- `tools/xtask/`：包名 `vaultsyncd-xtask`、二进制名 `xtask`，edition 2024、无第三方依赖，继承 `[workspace.package]` 与 `[lints] workspace = true`。加入 `members`，**不**进 `default-members`；`Cargo.lock` 仅新增该包 4 行。
- 根 `.cargo/config.toml` 只加一个别名 `xtask = "run --package vaultsyncd-xtask --"`，不设目标、镜像、链接器或网络行为。
- 子命令（完整契约见 `docs/architecture/interfaces.md`）：`env` 探测 rustc/cargo/node/pnpm 版本、`cargo tree --locked --workspace --depth 0` 成员与关键路径存在性，不写死版本；`check` 先确认 `node_modules` 存在（缺失即报错并提示 `pnpm install --frozen-lockfile`，不跳过 typecheck），再按序执行 `cargo fmt --check`、`cargo clippy --locked --all-targets -- -D warnings`、`cargo test --locked`、`pnpm --recursive run typecheck`，逐步打印命令与退出码并汇总失败步骤；`generate`/`package` 打印「未实现（Unsupported）」并退出 3；未知子命令与多余参数退出 2；`help` 退出 0。所有子命令在 workspace 根执行，可从任意子目录调用。
- `.github/workflows/checks.yml`：Linux runner 上的便携检查。工具链不重复写版本——Rust 走 `rust-toolchain.toml`（`rustup show`），Node 走 `package.json` 的 `engines.node`，pnpm 走 `packageManager`；缓存为 `actions/cache`（cargo registry/git/target，键含两个锁/工具链文件哈希）与 setup-node 的 `cache: pnpm`；检查入口是单步 `cargo xtask check`。
