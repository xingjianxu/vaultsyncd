# S056 — 本地 generation 与上传快照

状态：done（代码、契约、验证与受锁集成均完成）。

## 依据与接口决定

依据实施手册 S056、`docs/design.md` §8.3—8.4、§9.1、T04、S054/S055 交接。
主要落点为 `crates/agent-core/src/executor/upload.rs`：

- `UploadActionHandler` 按注册的 `OpId -> UploadSpec` 固定本地路径与 `Generation`，执行前后调用
  `LocalPort::observe`，期间通过 `LocalPort::snapshot` 取得固定只读源；前后 generation、大小和稳定
  file identity 不一致时返回 `LOCAL_CHANGED`，不发送旧快照的服务器提交。
- 上传复用 `transfer::upload::run` 与 `UploadResumeStore`。续传/块传输失败保留可恢复会话；固定快照
  变化时丢弃旧会话。finalize 仅产生内容引用，不当成 committed。
- 请求携带原 `OpId`、基线 revision/version、设备身份、server epoch 与 `local_generation`。提交网络
  响应丢失时用 `RemotePort::operation(binding, op)` 查询原 OpId，不生成新操作。
- 新增 `UploadCommitStore`/`UploadCommit` 契约：服务端 committed 后必须按 generation 条件写入
  baseline、ACK/冲突稳定 ID 映射并更新 dirty。`Applied` 与 `StaleGeneration` 都表示远端已 committed，
  但后者不得清除新 generation 的 dirty；只有该事务成功后才清理续传记录并让执行器出队。
- `docs/architecture/interfaces.md` 追加 S056 契约；`ChunkReader` 增加 `Send + Sync` 约束，使传输
  future 能安全通过 agent 的异步端口。

## 限制与下一步

`UploadCommitStore` 是 agent-core 的持久化契约；本卡未在 client-store 中新增第二套 baseline/冲突写入
API，也未把平台文件观察器接入 generation 分配。应用入口需用现有 client-store entries/baseline 与
本地观察适配器实现该契约，并保证条件更新与冲突映射同事务；这是后续接线的恢复条件，不影响本卡
对“只有 baseline 成功才清理/确认”的围栏。
