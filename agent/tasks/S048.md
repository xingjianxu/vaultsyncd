## 1. 接口决定

- **快照 = 创建时复制的短期清单**：`POST /v1/roots/{root}/snapshots` 在同一写事务里读 `roots.seq`
  （`high_water_seq`）并把活跃条目（含合成根条目、当前版本的 `version_id/size/hash`）复制到
  `snapshot_entries`；翻页只读这张表，因此“边写边翻页”不会漏/重/改名漂移。TTL 600 s，每 Root 最多 8 份未过期
  快照（超出回收最旧）。快照不存在/过期/他人的统一 **410 `CURSOR_EXPIRED`**（`details.reason=snapshot_expired`），
  不新增错误码（design §15.4 闭集已有 `CURSOR_EXPIRED`）。
- **`changes` 不拆事务**：`limit` 只决定在哪个事务边界截断；第 `limit` 个批次与后续批次 `tx_id` 相同且 seq
  连续则页延伸取完。一个 `changes` 行本身就是完整事务批次（多条事件在 `events_json` 数组里），所以“同事务多变更”
  天然不被切开。窗口事实（头/epoch/下沿）与批次同一读事务取得。
- **游标失效一律 410，绝不空集**：`after` 早于保留下沿（默认 90 天，`created_at < now-90d` 的最新批次的 seq）→
  `before_retention_window`；`after` 晚于当前头（服务端回退/伪造）→ `ahead_of_head`；`after == 下沿` 合法。
  保留窗口是逻辑下沿：`changes` 行被 `versions.created_seq`/`operations.root_seq` 外键引用，不能物理删除。
- **SSE 自己轮询 `roots.seq`**：不依赖进程内发布者（S052 的写路径、外部观察者、其他写者推进 seq 都会被提示）；
  只发 `event: seq` + `SeqHint{root_id,seq}`，不带事件内容；头不变不重复提示、头变小也提示；draining 时流结束，
  不拖住优雅停止。
- **生成器扩展（format v4→v5）**：`in: query` 标量参数（必填/可选，TS 收成 `query` 对象，只写给了值的可选项）；
  `text/event-stream` 成功响应（TS 返回原始 `Response`）。
- 新增 `domain::ids::SnapshotId`；迁移 `0007_snapshots.sql`（`snapshots`/`snapshot_entries`/`changes_by_time`）。

## 4. 限制

- 验收用 `tower::oneshot` 调 router（与 S045—S047 同法），未起真实监听/真实代理；SSE 的代理缓冲与真实断线重连未测。
- 保留期 90 天只是 `SyncConfig` 默认值，未接入 TOML；保留窗口是逻辑下沿（外键使物理删除 `changes` 行不可行）。
- `ServerEpoch` 变化后的旧游标没有显式 epoch 校验（`changes` 请求不带 epoch）；`ahead_of_head`/`before_retention_window`
  覆盖回退的常见形态，epoch 绑定属重建流程。
- 快照复制随 Root 条目数线性增长（每次创建一次全量复制）；每 Root 8 份上限与 600 s TTL 限定了存储；超大 Root 的分块创建未做。
- `events_json` 的事件字段由提交协调（S052）定义；本卡只保证整批返回，不解释其内容。
