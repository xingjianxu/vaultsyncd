## 1. 接口决定

- **唯一第三方依赖 `ignore`（ripgrep 的 gitignore 实现）**：design §4.1 明确“不自行拼写 glob 正则”，因此 glob 匹配、注释/空行/`!`/锚定/目录规则/字符类语义全部由该库执行，本 crate 不手写匹配器。写法为 `ignore = "0.4"`，由 resolver 3 的 MSRV 感知解析锁定 `ignore 0.4.30`（0.4.31 起声明 Rust 1.88，会打破 workspace 的 `rust-version = "1.85.0"`；`globset` 同理停在 0.4.19）。依赖只用于匹配：`Gitignore::new`、`GitignoreBuilder::add` 这两个会读文件的入口不使用，模块只接收文本，crate 仍无 I/O、无平台 API。
- **`ignore::DEFAULT_RULES`（`&'static str`，可编辑）**：默认清单是常量文本而不是硬编码分支，改它即改所有绑定默认。内容只列编辑器交换/锁/备份文件（`*~`、`*.swp`、`*.swo`、`*.swx`、`.#*`、`\#*\#`、`~$*`、`*.tmp`、`*.temp`）、下载中间文件（`*.part`、`*.partial`、`*.crdownload`）与桌面缓存元数据（`.DS_Store`、`._*`、`Thumbs.db`、`ehthumbs.db`、`desktop.ini`）；**不排除整个 `.git`、不排除任意隐藏文件、不排除 `.syncignore` 自身**（design §10.4 的两条反向要求）。
- **两个入口**：`IgnoreRules::parse_with_defaults(text)`（默认清单在前、绑定文本在后，按 Git “后面的规则优先”让绑定可用 `!` 覆盖默认）与 `IgnoreRules::parse(text)`（只用给定文本，供绑定提供完整清单替换默认）。
- **`IgnoreRules::decide(&RelativePath, is_dir) -> Decision`**：祖先目录按**自浅到深**检查，父目录被排除即返回该规则并停止——这复现 Git 的“父目录被排除后不能重新包含子项”。该库的 `matched_path_or_any_parents` 是叶子优先（ripgrep 自上而下遍历视角），与本设计相反，故不采用；库只提供单路径 `matched()`。
- **解释结构**：`Decision::{Included { reinclude: Option<Hit> }, Excluded(Exclusion)}`；`Exclusion { hit: Hit, blocked_reinclude: Option<Hit> }`，其中 `blocked_reinclude` 是查询路径自身命中的 `!` 规则（因祖先被排除而不生效）；`Hit { rule: String, source: RuleSource::{Defaults, Binding}, at: MatchedAt::{Path, Ancestor(RelativePath)} }`。`Display for Decision` 输出中文解释（CLI 的“为什么被排除”直接复用）。`RuleSource` 用匹配库的 `from` 标签区分默认清单与绑定规则，不读文件。
- **`IgnoreRules::is_excluded(...) -> bool`**：只要布尔结果时的入口，等价于 `decide` 的判定。
- **`RuleIssue`**：`Line { source, line, text, reason }` 与 `Build { reason }`，行号相对**各自来源文本**（叠加默认清单后绑定文本仍从第 1 行计数）；解析错误不静默丢弃。首行 UTF-8 BOM 与 CRLF 按 Git 习惯处理（Windows 编辑器常态）。
- **`path::RelativePath::prefix(len) -> RelativePath`（`pub(crate)`）**：仅用于解释里记录“命中的是哪个祖先目录”，S017 有意未预置的便利方法在此按实际用法补齐，未扩大公开 API。
- **排除不是删除**：本模块只有“参与/不参与”两种裁决，没有删除路径也没有删除事件类型；这一不变量写在 crate 文档、模块文档与 interfaces 文档里，由 `Decision` 的类型面保证（不出现 Delete 变体）。

## 4. 限制

- `ignore 0.4.30` 的行为即 Git gitignore 语义的“库实现”：大小写折叠与 Unicode 归一化**不做**，因此 `*.TMP` 与 `*.tmp` 是两个规则；跨平台大小写不敏感的文件系统上的匹配差异需要在接入平台层时用回归用例覆盖（当前按字节匹配，两端一致）。
- 默认清单是**建议默认值**，不是不可改的策略：用户可以用 `parse_with_defaults` 的 `!` 重新包含，或在 `parse` 里给完整清单。默认清单里的 `*.tmp`/`*.temp` 会排除真实的同名文档，这是“默认排除常见临时文件”的代价，已记录在常量文档里，改默认清单不需要改代码逻辑。
- 祖先排除采用“自浅到深第一条命中即停”，与 Git 的“不下降进被排除目录”等价；但没有实现 Git 的“父目录被重新包含后仍需要显式重新包含子项”的更细差别——本实现下 `build/` + `!build/` 会让子项正常参与同步，与 Git 一致，若将来需要逐条对齐 `git check-ignore` 输出，应在本文件补测试再改。
- 未接入扫描器/执行器：`decide` 的排除结论如何影响本地缺失判定与远端删除判断（design §10.4 “客户端不能据本地缺项推断整个远端目录应删除”、已跟踪条目的 excluded 状态）属于 agent/planner 侧后续卡，本卡只提供纯规则与解释，不产生任何删除。
- 规则文本来源（绑定级配置接口 vs 作为普通文件同步）由绑定配置卡决定；本卡只要求 `.syncignore` 自身不被默认清单排除，避免“规则文件被自己的规则排除而无法更新”的循环。
