## 1. 接口决定

### `crates/agent-core`（新建，进 `members` 与 `default-members`）

- **依赖方向**：`domain`/`fs-common`/`planner`/`protocol`/`transfer`/`client-store` + SQLx（只用于适配器
  的连接池与短事务）。不依赖 server-core/server-store/Tauri，不做平台 I/O（design §5.5）。
- **端口（`src/ports/`）**：`clock::Clock`（`domain::version::Clock` 的 `Send + Sync` 包装）、
  `local::LocalPort`（能力/观察/固定快照/受控替换/移动/删除/释放）、`remote::RemotePort`（以
  `OpId` 提交与查询 wire `OperationRequest/Result`、取上传与固定版本内容端点）、
  `state::{OperationStore, IntentStore, UploadResumeStore}`。**端口互相不引用**：只共享
  `PortError`/`PortFuture`，`ports::Ports` 是唯一组装点；`ports/mod.rs` 文档给出依赖表，测试用
  `include_str!` 逐字校验各叶模块不出现其它端口 trait 名，并单独验证每个端口可独立构造后任意组装。
- **`OperationKind`**：`pending_ops.kind` 的闭集（13 种，snake_case），`from_action(&planner::Action)`
  是规划器动作的唯一映射；`NoOp`/`Defer`/`PreserveBoth` 不产生操作。`local_write()` 指出哪些操作
  必须先落本地意图（apply→replace、move、release、create_from_remote→replace）。未知文本不猜。
- **`Executor<H>::run`**：按插入顺序串行调度（不用客户端时钟排序）。顺序固定为：暂停检查（暂停不
  读队列）→ 依赖就绪 → 尝试次数 → 退避到期 → 种类可解析 → `IntentStore::begin_intent` → 处理器执行。
  成功：`complete_intent` + 出队；`Pending`：不出队（I01）并记轮询到期；失败：`record_failure`
  累加 attempts 与错误码，可重试错误按 `RetryPolicy` 退避，用尽或 `NeedsUserAction`/`Corrupt` 时
  标记意图失败并阻塞——**失败操作与依赖方都不删除**，依赖方报告 `DependencyIncomplete`。
- **`RetryPolicy`**：默认 3 次、1s 起、60s 封顶；构造拒绝 0 次、>16 次、0 延迟与上限小于起点；
  `delay_after(n)=min(base·2^(n-1), max)`，无抖动（S062）。
- **暂停**：`PauseReason::{UserRequested, Offline, RootUnavailable, BindingDisabled}`；暂停只是输入，
  不改任何状态，恢复后队列原样继续。
- **退避到期时间**只存在进程内（`Mutex<HashMap<OpId, UtcTimestamp>>`），避免同一进程内连续 `run`
  立即烧光有界次数；跨重启持久化属 S062。
- **执行器自身的失败**：`ExecutorError::{Port, DuplicateOp}`；端口失败中止本轮，队列保持原样；重复
  `OpId` 属数据损坏，不执行任何操作；依赖成环只标记真正成环的一段（环前驱报告依赖未完成）。

### `crates/client-store`（迁移 0003）

- 新增 `upload_resumes`（S054 遗留落点）：`op_id` 主键并外键 `pending_ops(op_id) ON DELETE CASCADE`，
  记录 `snapshot_identity`/`total_size`/`digest(32B)`/`session_id`；**不存块位图**（已收块以服务端
  `upload_parts` 为准，design §9.3）。`save` 用 `ON CONFLICT DO UPDATE` 整条覆盖（快照与会话一起写），
  `load`/`discard` 与坏行拒绝。schema 目标版本 `2 → 3`；db 迁移测试同步更新。
- 下载进度**不新建端口**：`adapters::client_store` 实现 `transfer::ports::DownloadProgressStore`，
  映射到既有 `transfers`（`chunk_size`/`total_size`/`temp_path`/`bitmap`）：位图只增不回退、几何或
  临时路径变化即作废旧进度、位图完整时 `complete_transfer`（verified=1）、已完成记录重复保存幂等；
  `cancelled`/`failed` 终态不返回可用进度（该行不再接受更新，旧行由 `discard` 清理）。

## 4. 限制与阻塞

- **执行器不实现上传、下载与本地替换**：这些是 S056（上传快照/ACK 代际）与 S059（受控应用/重启
  核对）的 `ActionHandler`。本卡只固定“先意图后动作、失败保留、重试有界、暂停不丢队列”的顺序与
  报告形状；`transfer::upload::run`/`download::run` 尚未在 `ActionHandler` 中接线。
- **`UploadResumeStore` 只有端口与 SQLite 适配器**：S056 接入上传执行器时按其
  `UploadResume`/`SnapshotChanged` 语义使用；本卡没有真实上传端点联调。
- **退避不跨进程持久化**：`pending_ops` 没有 `retry_after` 列，重启后立即重试（次数仍有界）。
  跨重启退避与 jitter、每文件有界并发、用户读取优先属 S062。
- **本地删除没有 `local_intents` 种类**：`apply_remote_delete`/`delete_entry` 的可恢复性由
  `pending_ops` 与远端事实承担（design §7.3 只定义 replace/move/release/import）；执行器要求
  现场代际相符由平台端口负责（S059）。
- **意图复用是“先查后写”**：同一事务内查询同路径意图并复用/拒绝；并发写同路径时数据库 `UNIQUE`
  冲突会冒泡为 `Local{Write}`，不会写出第二条意图。
- **下载进度不存 `entry`**：`transfers` 以 `(binding, version)` 为主键；同一 `VersionId` 只属于一个
  条目（I12），版本身份足够区分。`cancelled`/`failed` 终态不返回进度，调用方重新开始时旧行由
  `discard` 清理（S031 的终态语义不变）。
- 未做真实服务端/平台联调（本批 L 卡范围）；Windows 原生能力仍待 S065 起的卡验证。
