## 1. 接口决定

- **新模块 `crates/planner/src/conflict.rs`**（同 crate，不新建包）：输入 `ContentConflictRequest { base, local, remote, conflict_entry_id, committed, naming }`，输出 `Result<ConflictPlan, ConflictPlanError>`；`ConflictPlan { main: Plan, copy: ConflictCopy }`。仍是纯规则：不读时钟、不分配身份、不枚举同级条目、不做 I/O。
- **只接一种输入**：路径与类型未变、两侧都相对基线改了内容、两侧 `ContentFingerprint`（长度 + SHA-256）不同。其余形态一律 `Err(NotContentConflict)` 交回 `reconcile` 的对应分支（无操作/应用远端/本地提交/同结果归并/延期裁决），不抢 S022 的移动、删除、文件—目录同名裁决。
- **主条目保留服务器 head**：`main` 直接复用 `reconcile::apply_remote`（改为 `pub(crate)`，前提与保护说明只有一份定义），动作 `ApplyRemote { revision, version }`，前提 `BaseRevisionCurrent`/`GenerationUnchanged`/`UsagePermitsChange`/`TargetPathUsable`，保护 `SnapshotBeforeReplace { generation }`（替换本地字节前先固定快照，I02）。依赖追加 `Dependency::ConflictCopyCommitted { entry_id }`，声明为 `Dependency` 的最后一个变体，因此顺序是先下载、再提交冲突副本，最后才替换本地字节。
- **迟到分支的新条目**：`Action::CreateConflictCopy { entry_id, op_id, generation }`（新增到 `reconcile::Action`）；路径用 `conflict_entry_path` 生成在同一父目录，前提 `BaseRevisionCurrent { expected: remote.revision }`/`GenerationUnchanged`/`TargetPathUsable`，依赖 `ParentDirectoryReady` + `SnapshotLocalContent`，保护 `UploadSnapshot`。
- **稳定副本身份 = `OpId` 决定，不靠文件名**：`conflict_entry_id` 由服务端为该 `OpId` 首次分配（`IdSource`）后与结果同事务持久化；重试传回 `committed: Some(&CommittedConflict { op_id, entry_id, path, content })` 时 `copy` 为 `ConflictCopy::Reuse`，返回原 `entry_id` 与原 `path`（即使设备短标识或服务器时间已变也不改名）。同一 `OpId` 的内容或身份不同 → `Err(OpIdRequestChanged)`（I06「同 ID 不同请求拒绝」）。planner 不自造哈希：身份不由名称或内容推导。
- **冲突名称（§10.2）**：`conflict_entry_path(&RelativePath, &ConflictNameRequest)` → `<原名干>（冲突-<设备短标识>-<服务器时间>-<op 短标识>）<扩展名>`；扩展名保留（按最后一个 `.`，首个字符为 `.` 的名称整段算原干）；时间只取传入的服务器时间（`UtcTimestamp` → `20261105T083000Z`，内部用纯整数 `civil_from_days`，不引入日历库也不读时钟）；原名干按名称预算 `NameBudget { utf8_bytes, utf16_units }` 以字符边界截断，后缀与扩展名先占预算；组合结果过 `fs_common::name::validate_name` 再 `RelativePath::parse`，失败返回明确原因而不是静默改写。
- **短标识长度可扩展**：`ShortIdLen`（`DEFAULT` = 8，范围 8—32，`extended()` 翻倍），撞名时加长换名，不改变身份；后缀本身超出预算返回 `SuffixExceedsBudget`，不放宽到丢身份信息。
- **不做的**：不在 planner 里检测同级名称是否已被占用（执行器按 `TargetPathUsable` 核验后重新规划）；不做文件—目录同名、移动后冲突、删除/恢复冲突（§10.1 其它行 = S022）；不把冲突副本的“来源元数据”落成新结构——`op_id` 已在动作里，来源条目身份由调用方从 `remote` 事实取。

## 4. 限制

- 只覆盖 §10.1「两端修改内容且字节不同」一行。file/dir 同名、移动后目标冲突、删除/修改与删除/移动、`SUBTREE_CHANGED` 都仍由 `reconcile` 输出 `Defer`，等 S022 落地；本卡对它们返回 `NotContentConflict` 而不是抢着造副本。
- T02/T03 的端到端验收（三台客户端、`OpId` 提交成功但响应丢失）还需要服务端幂等表与 HTTP 层（S028/S036/S047）与 agent 执行器（S055+）。本卡保证的是规划层语义：同输入同计划、同 `OpId` 返回原身份原路径、不因重试新增副本、名称与身份解耦。
- `ConflictCopy::Reuse` 依赖调用方把“冲突条目 + 该 `OpId` 结果记录”放在同一事务提交（I01）；若服务端先提交了条目却丢了记录，规划层无法补救——需要 S036 的幂等记录与恢复测试覆盖。
- 名称预算只作用于单个名称分量；父路径接近 `RelativePath` 整体上限（4095 字节）时组合路径会返回 `ConflictNameError::Path`，需上层缩短预算或告警，不自动改写名字。
- 名称中的设备短标识由调用方给出（`&str`），planner 只做“最终名称可跨端表示”的校验，不负责从 `DeviceId` 派生该标签；撞名扩展只提供 `ShortIdLen::extended`，实际重规划由执行器触发。
- `ContentFingerprint` 仍是调用方传入的长度 + 摘要；接入 `crates/transfer` 时不要保留第二套比较语义（同 S019 限制）。
