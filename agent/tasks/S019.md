## 1. 接口决定

- **新 crate `crates/planner`（`vaultsyncd-planner`）**：design §5.4 指定的三方比较模块。只依赖 `vaultsyncd-domain` 与 `vaultsyncd-fs-common`，无第三方依赖、无 I/O、无平台 API；加入根 workspace 的 `members` 与 `default-members`（可移植核心，`cargo test/clippy --locked` 直接覆盖）。本卡只落 `src/reconcile.rs`；`first_sync.rs`/`conflict.rs`/`rename.rs`/`delete.rs` 留给 S020—S022，不预置占位。
- **事实类型分两侧**：`ServerFact`（B 与 R）带 `entry_id`、`revision`、`version: Option<VersionId>`；`LocalFact`（L）带 `generation`。分开的原因是本地根本没有服务器修订，用同一个带 `Option` 字段的结构会让“本地也带修订”这种无意义组合可表示。两侧都有 `path`、`kind: EntryKind`（`File(ContentFingerprint)` | `Directory`）与 `observed_mtime`。
- **`ContentFingerprint { size, sha256 }`**：内容等价判定值。`ContentHash` 在 design §7.1 属内容哈希，S015 已决定它归 `crates/transfer/hash.rs`；本卡不新建第三个哈希实现，只要求调用方把算好的摘要(长度+32 字节)以值传入，规划器不读字节。文件与目录的区分放在 `EntryKind`，目录没有内容版本（I12）。
- **“同一结果”= 位置 + 类型 + 内容都相同**（`Shape::same_result`），只看这三个字段，不看 `mtime`、`EntryId`、`Revision`、`generation`。`mtime` 仅随事实记录（展示/候选变化检测，I04）；长度相同但摘要不同、或仅 `mtime` 相同都不归并。`same_location_and_kind` 额外用于“位置/类型是否变化”的前置判定。
- **“是否有变化”两侧证据不同**：“R=B”要求远端 `Revision` 等于基线且形状相同（服务器只在条目变化时递增修订）；“L=B”只能按位置/类型/内容判定。任一证据显示变化即算有变化——宁可重新规划，也不把过期基线当无操作；因此“远端只推进了修订、内容未变”仍生成 `ApplyRemote`，但**不要求下载**、也不替换本地字节。
- **`Plan`**：`path`（优先基线位置，其次本地，再其次远端）+ `action` + `prerequisites` + `dependencies` + `local_protection`；纯值，不承诺执行成功。三项都缺失返回 `PlanError::NoFacts`，不编造计划。
- **动作**：`NoOp`、`ApplyRemote { revision, version }`、`UploadLocal { base_revision, generation }`、`MergeSameResult { revision, version }`、`Defer(DeferReason)`。`DeferReason` 每个取值都对应一条本卡不实现的规则：`FirstSync`（§9.2/S020）、`MissingEntry`（§10.3/S022）、`IdentityReplaced`（I03，原条目删除后同路径新建是新身份）、`LocationOrKindChanged`（§9.5/§10.1、S022）、`ContentConflict`（§10、S021）、`IncompleteFacts`（自称内容变化却没有 `VersionId`，不降级成“只推进元数据”）。
- **前提**：`BaseRevisionCurrent{expected}`（提交/应用前 CAS 复核）、`GenerationUnchanged{expected}`、`UsagePermitsChange`（§9.1 要求远端应用前查使用保护）、`TargetPathUsable`（路径条件：父目录已同步、名称可表示、无同名另一类型条目）。**依赖**：`DownloadVersion{version}`、`ParentDirectoryReady`、`SnapshotLocalContent{generation}`。顺序固定为声明顺序，便于执行器逐项核对与测试比较。
- **本地内容保护**：`NotNeeded`（无操作）、`KeepLocalContent`（字节不动，只在基线写入后推进状态：归并与所有延期裁决）、`SnapshotBeforeReplace{generation}`（远端内容变化，替换前固定快照）、`UploadSnapshot{generation}`（上传固定该代际，上传期间新写入属后续代际，旧 ACK 不得清除，I02）。
- 未做：**不使用 `fs_common::name`/`path::relation`**——本卡不创建名称（冲突改名归 S021）也不判定目录重叠，路径本身已是 `RelativePath`；不提供父目录导航（`RelativePath::parent`），`TargetPathUsable`/`ParentDirectoryReady` 不携带路径值，由执行器按 `Plan::path` 推导，避免在 fs-common 里提前加只有一处使用的 API。

## 4. 限制

- 本卡只实现 §9.1 的四条基本分支：首次合并（S020）、内容冲突副本（S021）、移动/删除矩阵（S022）都不在此处，遇到这些输入只输出 `Defer`。`Defer` 不是“已同步”也不是“已裁决”，执行器/上层必须按对应规则继续处理，不能把它当终态。
- 远端修订被视为“服务器只在条目变化时递增”的可靠证据；若同修订下内容不同（服务端 bug 或陈旧快照），`remote_unchanged` 因还要求形状相同而按“有变化”处理，但不区分具体是哪个字段变了。
- 比较只看单条目自身事实：父目录/子树状态、目录环、同名另一类型条目只作为 `TargetPathUsable`/`ParentDirectoryReady` 前提交给执行器核对，规划器不枚举同级条目，也不做名称等价判定（`NameEquivalence` 归 S065）。
- `ContentFingerprint` 是规划器的比较视图，不是新的 SHA-256 实现；接入 `crates/transfer` 时需把其内容哈希映射到这个值（长度 + 32 字节摘要），届时不要保留第二套比较语义。
- `observed_mtime` 用 `UtcTimestamp`（整秒），只作展示/候选变化提示；它不能用于判断“文件未变”（design §9.1 末段：两次 stat 相同也不是原子快照证明）。
- 计划不携带 `OpId`/任务 id：幂等与排队归 agent-core 的执行器卡，本卡不预置。
