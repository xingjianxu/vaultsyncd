## 1. 接口决定

- **`files::root`（新，正式接口）**：`RootHandle::open(path, ResolveMode)` 先 `probe_path` 读内核事实，再以 `O_DIRECTORY|O_NOFOLLOW` 打开规范路径，并核对句柄身份与探测事实是同一个目录（设备/inode/btime/挂载 ID 任一不符 → `root_changed_during_open`）。内核不提供 `STATX_MNT_ID` 时直接 `mount_id_unavailable`（fail-closed），不假装能核对边界。方法：`list_dir`/`open_read`/`create_exclusive`/`identity`/`verify`/`path`/`facts`/`snapshot`/`mechanism`；空相对路径表示 Root 自身。
- **挂载边界是每次访问的复核项**：列举、打开、创建的对象的 `STATX_MNT_ID` 必须等于 Root 的挂载 ID，不同 → `mount_boundary_crossed`，缺失 → `mount_boundary_unverified`。`create_exclusive` 先打开并核对**父目录**，再用那个句柄建文件，因此 bind mount 进 Root 的外部目录既不会被列举、也不会被写入（不会“先照路径建、事后才发现跨挂载”）。
- **身份复核**：`RootSnapshot` 记录 `resolved_path/backend/fs_magic/fsid/subvolume_id/mount_id/dev_major/dev_minor/inode/btime`，`to_spec`/`parse_spec` 是唯一编解码（缺字段、重复字段、非法值都报错）。`compare(facts)` 按“后端 → FSID → 子卷 → 挂载 → 目录身份”返回首个 `RootDrift{backend_changed,filesystem_changed,subvolume_changed,mount_changed,directory_changed}`，`design_error_code()` 恒为 `ROOT_UNAVAILABLE`（运行期漂移暂停 Root，不推导删除）。`RootHandle::verify()` 同时复核“句柄自身仍是那个目录”与“路径仍指向同一存储单元与挂载”。
- **目录列举走句柄**：`RestrictedDir::list_entries()` 用已打开目录句柄的 `getdents64(2)`，不用 `read_dir(路径)`；丢弃 `.`/`..`、按名称字节序排序、符号链接只报 `EntryKind::Symlink` 不跟随。权限/读目录失败返回 `permission_denied`/`read_dir_failed` 并保留原始 `io::Error`，**不用空列表代替失败**。
- **`getdents64` 的架构处理**：`__NR_getdents64` 不在 `asm-generic` 编号里，按 `x86_64=217`/`aarch64=61` 声明；其它架构返回 `Unsupported` 错误而不是空目录。`linux_dirent64` 解析是纯函数（长度越界、名称未 NUL 结尾都报错），头部长度 19 与 `DT_*` 有自检。
- **`mounts::overlap`（新）**：`DirectoryRecord{role: root|internal, facts}` + `find_overlaps`。同一规范路径 → `same_path`；同一目录对象（设备+inode+btime）经不同路径 → `alias`（bind mount 的两条路径挂载 ID 不同也照样识别）；内部目录落在 Root 内 → `internal_inside_root`；Root 落在内部目录内 → `root_inside_internal`；其余父子 → `parent_child`（按路径分量，`/data/root` 与 `/data/rootx` 无关）。只判定并报告，不决定“是否允许”。
- **`BackendKind::parse`**：与 `as_str()` 互逆，供快照规格读回；后端分类规则不变。
- **未做**：递归扫描策略与条目上限（S049 的采集）、目录创建/同 Root 移动（S038）、`fs_intent`/Epoch 流程。`RootHandle` 不判定后端是否合规（`mounts::admission` 的职责），以便在注册流程之外复用。

## 4. 限制

- 需要内核提供 `STATX_MNT_ID`（≥5.8）才能使用 `RootHandle`：更老的内核一律 `mount_id_unavailable`，本卡不做退化方案。
- 挂载边界只按挂载 ID 判定；同一挂载内用 `..`/符号链接的别名由 `RESOLVE_BENEATH|RESOLVE_NO_SYMLINKS` 与相对名称校验挡住，不做“同一挂载内两次绑定同一目录”的额外检测（那属于 `mounts::overlap`）。
- `list_entries` 不设条目上限（递归扫描策略与上限留给 S049）；大目录一次性收集到 `Vec`。
- 竞态验收只覆盖“换目标”与挂载覆盖这类外部非协作变更，不是高并发压力测试；`RootHandle::open` 的 TOCTOU 检测是“发现不一致就失败”，不宣称消除窗口（C33）。
- `getdents64` 只声明 x86_64/aarch64 的调用号；其它架构返回 `Unsupported`（首发范围不含）。
- 本 crate 仍不在 workspace `default-members`，`cargo xtask check`/CI 不构建它；worktree 无 `node_modules`，未跑前端检查。
