## 1. 接口决定

契约摘要见 `docs/architecture/interfaces.md`「inotify 与溢出补扫（S050）」。要点：

- **事件只是线索**：平台 `DirWatcher` 只产出 `WatchSignal::{Changed, Subtree, Overflow, Gap}`，没有“删除/写完”语义；路径现在是什么仍由 `WorkTreePort` 实测。监视对象是已打开的目录句柄（`/proc/self/fd/N`），先登记后列目录，新目录先登记再发 `Subtree`。
- **溢出/重启立即补扫**：内核队列溢出 → 平台丢弃并重建整张监视表 → `Overflow`；核心 `HintQueue` 里 `Overflow` 不经去抖、下一次取用立即要求全量补扫；`FollowDriver` 第一次 `step` 一定是 `Startup` 全量补扫（调用方须先建监视再补扫）。线索队列有界，满了退化成全量补扫而不是丢线索。
- **三层兜底**：线索观察（去抖 300 ms，之后走原稳定窗口）、周期元数据扫描（默认 60 s；上次读不了/Root 不可用 5 s 后重试，预算耗尽立即续扫）、分批内容复核（默认每 10 s 64 个，已采纳基线现含内容摘要，复核发现“指纹没变但内容变了”即撤下基线、重新等待窗口）。
- **忽略自己的写入按身份/意图，不按时间**：`ExternalObserver::expect_own_write` 登记（设备+inode+内容），观察到时 inode 相同且摘要相同才忽略；inode 不同 = 不是它（用户 rename-over，意图保留）；同 inode 内容不同 = 外部修改（意图作废并采纳）。账本有界，满了拒绝登记而不淘汰。
- **不推导删除**：线索观察/复核看到“不存在”只记入报告 `absent`；读不了记入 `unreadable` 保持原状；权限缺口作为 `Gap` 上报，靠周期扫描与重试覆盖，权限恢复由父目录/自身属性事件触发 `Subtree` 补扫。

## 4. 限制

1. **没有后台任务**：`apps/server` 尚未按 Root 启动 `RootWatcher` + `FollowDriver` 循环；`RootWatcher::pump` 是同步阻塞读取（进程入口应放 `spawn_blocking` 或自己的线程）；监视出错/挂载变化后的重建由入口负责。
2. 已采纳文件的外部删除/改名管线（rename cookie 配对、回收站）不在本卡：观察到不存在只记录。
3. **自写意图尚无调用方**：登记/释放 API 与判定已就绪并有测试，等服务端写入发布路径接入（需要在 `renameat2` 前登记暂存文件的 inode、提交后释放）。
4. 内容复核用候选采集（reflink/复制 + 哈希 + 发布同内容对象）实现，开销较大；对象区会因此产生“已存在”的幂等发布。后续可在端口上增加只读哈希。
5. 去抖只合并同路径事件，持续写入的路径会一直不被交出（线索被不断刷新）；这类文件由周期扫描与稳定窗口兜底，不会被无休止传播。
6. `inotify` 受 `max_user_watches` 与目录数限制；超出的目录报 `Gap` 只靠周期扫描覆盖（60 s），不满足 1—3 秒目标（C39 同款边界，设计已说明）。
7. 平台 `/proc/self/fd/N` 方式要求 `/proc` 可用（挂载准入本来就依赖 `/proc/self/mountinfo`）。
