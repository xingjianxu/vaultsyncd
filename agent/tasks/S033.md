## 1. 接口决定

- **新建 `crates/server-core`（`vaultsyncd-server-core`）**：按 design §5.4 承载服务端用例核心。本卡只落 `objects/` 与 `ports/`；无第三方依赖、不做平台 I/O，因此进 `default-members`，便携检查就能回归对象规则。
- **端口定义在核心，平台库不反向依赖核心**：`ports::object_store::ObjectBlobPort` 是字节层契约（`stage_working_copy`/`publish_staged`/`discard_staged`/`verify_object`/`read_object`），由适配器实现并报告实测事实。`platform-linux-server` 的库保持零依赖，只有 `examples/object-capture.rs` 这个入口（S033 的“本地 wrapper 组装”）用 `dev-dependencies` 接核心，避免平台层与核心互相依赖（design §5.5）。
- **判据在核心，不在端口**：副本必须与源是不同 inode、且没有额外硬链接（不得用共享可写 inode 冒充不可变副本，design §11.1/C37）；长度与 SHA-256 必须等于期望内容；内容地址已有对象时不覆盖，复核通过才算复用；发布后再复核一次（I12）。
- **失败一律不可提交**：`CaptureFailure { reason, staging: not_needed|discarded|failed }`，`is_committable()` 恒为 `false`。端口报错时核心不重复丢弃（端口契约要求自己清理未验证副本）；发布失败与复用路径由核心丢弃并如实报告清理结果。
- **`BlobError` 分类保留原始原因**：`StorageFailure::{NoSpace, QuotaExceeded, Io, PermissionDenied, ReadOnly, Other}`，`code()` 给稳定短名；ENOSPC 不会伪装成“不支持 reflink”或成功（design §11.5）。
- **布局由核心固定**：暂存 `<objects>/staging/<名字>`，对象 `<objects>/objects/<aa>/<64 位 hex>`；`relative_object_path` 就是写 `objects.storage_path` 的规范相对路径（S028 的 `storage_path` 全库唯一依赖这一点）。暂存名必须是单个文件名，核心在任何 I/O 之前拒绝 `../` 之类逃逸。
- **读取以元数据为准**：`read_object(port, layout, digest, expected_bytes)` 的长度来自 `objects.size`，不用实测长度反推元数据；摘要不符返回 `digest_mismatch`，不把改写后的字节当成该版本。
- **适配器语义**：暂存与发布都在对象区，发布用 `RENAME_NOREPLACE`、成功后刷目录、对象权限 `0444`；`FICLONE` 优先，`EXDEV`/不支持退回 `stage_copy` 的校验复制并暴露 `exdev`/`unsupported`。
- **未做**：`fs_intent`、提交调度锁、Entry Revision/现场指纹复核（S034/S035）、对象行的数据库写入与 GC 引用（`record_object` 已有，属提交卡）、上传暂存（S045/S046）、`apps/server` 的真实进程组装（S044 起）。

## 4. 限制

- **端口契约靠适配器兑现**：核心只能校验端口报告的事实；“副本确实是新 inode”“读回校验真的做了”由适配器实现（S014 的 `stage_copy` 已实现并测试）。当前唯一的真实适配器是 S033 的示例入口，`apps/server` 的正式组装属后续卡。
- **对象区目录创建不在核心**：`<objects>/objects/<aa>` 与 `staging` 由适配器 `create_dir_all`；核心只决定路径。正式部署时由 Root/对象区注册流程建好目录（S044 起）。
- **不写数据库**：本卡不调用 `record_object`/`record_version`，因此“对象已发布但未写行”只会成为孤儿对象（design 允许），不会产生可提交引用；行写入与事务顺序属 S034/S035。
- **复核读一遍对象**：`verify_object` 在发布后再读一遍全量内容；大对象有额外 I/O 成本，正式路径是否复用 stage 阶段的读回结果，由后续性能卡（S106/S107）决定。
- **未覆盖**：源在副本建立期间被改写（S014 的 `source_changed` 已有真实样本）、对象区被并发 GC 删除后的读取、只读文件系统（核心分类已建，真实样本未造）。
- **`run-objects.sh` 依赖宿主布局**：工作区与对象区默认用仓库所在 btrfs（`artifacts/s033/…`），跨卷用 `/tmp` tmpfs、满盘用小 tmpfs（需要非交互 `sudo`；缺失时该用例跳过并记日志）。
