## 1. 接口决定

- **新 crate `crates/fs-common`（`vaultsyncd-fs-common`）**：design §5.4 指定的纯规则模块。无第三方依赖、无 I/O、无平台 API（系统调用留在平台层），加入根 workspace 的 `members` 与 `default-members`，因此 `cargo test/clippy --locked` 默认覆盖它，不需要额外特性开关。
- **`name::validate_name(&str)`**：按固定顺序检查并返回第一个原因——空 → NUL → 分隔符 → `.`/`..` → 控制/非法字符 → 长度 → 尾部点/空格 → 保留名。规则取 Linux 与 Windows 可表示性的交集，**不改写名称**（不小写、不做 NFC/NFD、不替换字符、不截断），符合 design §16.2“明确问题、由用户选择兼容名称”。
- **`name::NameIssue`** 是问题分类而非“已修复名称”：`Empty`、`NonUtf8`、`Nul`、`Separator`、`CurrentDirectory`、`ParentDirectory`、`Control(char)`、`Illegal(char)`（`< > : " | ? *`）、`TrailingDot`、`TrailingSpace`、`Reserved(ReservedName)`、`TooLong{utf8_bytes, utf16_units}`；实现 `Display`（中文原因）与 `std::error::Error`。
- **`validate_name_bytes(&[u8])`**：非 UTF-8 明确归为 `NonUtf8`（design §16.2“不做有损解码”），其余走同一规则，供 S032/S065 直接把 `OsStr` 字节交进来分类。
- **保留名判定**：列表 `CON`/`PRN`/`AUX`/`NUL`/`COM1`—`COM9`/`LPT1`—`LPT9`，加上 Windows 文档列出的上标形式 `COM¹`—`COM³`、`LPT¹`—`LPT³`；只看第一个 `.` 之前的部分且大小写不敏感，因此 `con.txt`、`nul.tar.gz` 都是保留名，`CONS`、`com0` 不是。`ReservedName` 只承载规范写法供报告，不替代用户名称。
- **长度双上限**：`MAX_COMPONENT_UTF8_BYTES = 255`（Linux `NAME_MAX`）与 `MAX_COMPONENT_UTF16_UNITS = 255`（NTFS 组件上限）必须同时满足；100 个汉字（300 字节 / 100 码元）报 `TooLong`。整体路径上限 `MAX_RELATIVE_PATH_UTF8_BYTES = 4095`（`PATH_MAX` 减 NUL）；Windows 绝对路径上限取决于 Root 挂载前缀，明确留给平台层（S065）。
- **`name::NameEquivalence` 端口**：`fn equivalent(&self, left, right) -> bool`，由平台层用真实比较表实现（Windows `CompareStringEx`、文件系统归一化），补齐 S065 的原生等价验证。端口**只回答是否等价、不提供改名能力**，因此接入原生语义不会造成静默改名。默认 `PortableNameEquivalence` 用“字节相同或 Unicode 小写折叠相同”（`str::to_lowercase`，仅比较），覆盖 design §16.2 的 `a.txt`/`A.txt`；不做 NFC/NFD，组合形式差异留给原生端口，判定偏保守（宁可报冲突）。
- **`name::find_collisions(names, &impl NameEquivalence)`**：按 `(first_index, second_index)` 升序返回 `NameCollision`，只报告不消解（design §16.2/§7.4：禁止静默覆盖另一条目）。文件与目录同名的**语义**处理（design §7.4）属于 planner/store，本模块只按名称等价判定，不引入条目类型。
- **`path::RelativePath`**：已校验的相对路径，`parse(&str)`/`FromStr`/`components()`/`Display`（以 `/` 连接，往返不改文本），实现 `Eq`/`Hash`/`Ord` 便于状态键使用。解析**只判定不修复**：`a//b`、`a/`、`./a`、`a/../b` 都报错，而不是折叠成另一条路径。
- **`path::PathIssue`**：`Empty`、`Absolute`（`/`、`\` 开头，含 UNC 与 `\\?\`/`\\.\` 设备路径）、`DriveLetter(char)`、`Nul`、`Backslash`、`EmptyComponent{index}`、`Component{index, issue: NameIssue}`、`TooLong{utf8_bytes}`；分量问题带上 0 基下标以便定位。
- **重叠判定按分量**：`path::relation`/`path::is_within` 返回 `PathRelation::{Same, Ancestor, Descendant, Unrelated}`；`a` 与 `ab` 是 `Unrelated`，明确不用字符串前缀（acceptance 项）。
- **未实现**：`ignore.rs`（S018）、`fingerprint.rs`（文件事实类型，后续卡）不预置占位；不做绝对路径分量关系（平台层 S032 已有 `mounts::paths`，「同一设备重复映射重叠目录」需要卷/目录身份，留给该卡）。

## 4. 限制

- `PortableNameEquivalence` 不等于任何具体平台的大小写/归一化表：它不做 NFC/NFD，因此组合形式不同的两个名称（`é` 与 `e`+`U+0301`）默认判为不碰撞。真实判定必须在 S065 用原生比较表实现端口；本卡只提供端口与确定性默认值，未做 Windows 实测。
- `RelativePath` 只表达 Root 内的相对路径，不含 Root 身份或卷信息；绝对路径的分量关系与「同一设备重复映射重叠目录」（design §16.1）仍由平台层与后续注册卡判定。
- 未提供 `strip_prefix`/`join`/父目录导航等便利方法：planner、ignore 真正的用法在 S018/S019 卡里出现，本卡不预置未使用 API。
- `find_collisions` 为 O(n²) 两两比较，适合单目录条目量级；超大目录批量检测的索引化留给实际性能卡。
- `Illegal` 只覆盖 Windows 非法字符集与 `U+0000`—`U+001F` 控制字符，不拒绝 `U+007F`（两平台均可表示），也不判决 ADS 等流语义（design §16.2 由平台层检测/记录）。
