# S174 — ZIP 同目录覆盖后自动采纳归属

状态：done（实现、文档与宿主可执行检查完成；Windows 原生断言待客体执行）。
依据：用户 2026-11-10 明确要求；design §19.3、§24（ADR-030）；前置 S109/S162/S167 done。

## 结果

用户把新版本 ZIP 解压覆盖原程序目录后，启动报 `ZIP_OWNER_MISMATCH`（`zip-owner.json` 仍钉住旧清单），且候选 `--auto-update` 也无法自救（候选与已装程序相同/同版本被拒）。按用户知情选择实现最宽松的一档：

- 同目录、`verify_zip` 自洽（十项文件逐项 hash/字节、`source` 与 `installed-files.json` 一致）时，启动**自动采纳**：重写 `zip-owner.json` 的清单摘要并追加审计行，然后正常启动；
- **不做任何备份**，因此没有程序回滚、没有整套状态回滚；不排空传输、不导出未确认内容；
- **版本方向不参与判定**（同版本重装、降级都会被采纳）；
- 自动更新入口不变（仍为 Latest 正式版 + 原归属路径 + 维护事务）；
- 跨解压目录/移动改名、安装版↔ZIP 互转、清单与文件不符（手工只换部分 EXE）仍拒绝；`maintenance.json`/`auto-update.json` 事务屏障优先于采纳。

## 接口

- `portable::resolve_owner(owner, program, manifest, state)`：程序目录不同 → `ZIP_OWNER_MISMATCH`；摘要相同 → 无操作；摘要不同 → `adopt_owner`。`portable::admit`（`--config` agent、session launcher、ZIP 入口）与 `claim()` 既有 owner 分支改用该函数。
- `portable::adopt_owner`：writer 锁空闲时取 `InstanceGuard`（agent 自身二次校验时为“忙”，继续并记录）；追加 `%LOCALAPPDATA%\vaultsyncd\zip-owner-adoptions.jsonl`（`unix_seconds`、`program`、`previous_manifest`、`manifest`、`writer_lock_acquired`、`program_backup=false`）；再用排他写句柄重写 `zip-owner.json`。owner 结构不变（`format/program/manifest`），旧二进制仍可解析。
- `portable::check_owner` 保持严格，仅供 `maintenance_owner`（自动更新前置）与 `claim()` 首次认领后的并发复查使用。
- `maintenance::admit_startup`：先查 `maintenance.json` 与 `auto-update.json` 屏障再查 ZIP 所有权，中断事务返回 `MAINTENANCE_REQUIRED`，不会被采纳顺带“修好”。
- 无 wire/schema/迁移变化；无新增 IPC 命令。
