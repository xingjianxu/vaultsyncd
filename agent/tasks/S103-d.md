# S103-d — 数据/元数据 ENOSPC 与 reflink 后 CoW 分配失败

状态：done。父卡：`agent/tasks/S103.md`。需求/验收：T21；I01、I02、I13。
落点：`tests/server-integration/tests/volume_exhaustion.rs`、`tests/server-integration/run-volume-faults.sh`（均新增）。
产出提交：`42ab10d`、`ca16195`。

## 装置

`test-volume.sh` 建两块互不相同的 256M btrfs loop 卷：
- 工作盘：Root + 内部状态同卷（准入要求）；用 4 MiB 大块写满数据块。
- 状态盘：Root + 内部状态同卷；用 ~1.5 KiB 内联小文件压元数据，若仍能分配新元数据块，就用数据填满卷阻止新块，再继续创建小文件直到真实 ENOSPC。
- reflink：先对 8 MiB 源做真实 FICLONE，再耗尽数据+元数据，对克隆写入。

脚本 `trap EXIT`：释放/删除本 run 镜像、detach loop、删除子卷；两卷 verify PASS 且 cleanup status=0。

环境变量：`VAULTSYNCD_S103_WORK_VOLUME`、`VAULTSYNCD_S103_STATE_VOLUME`（未设置时用例显式跳过）。

## 判据与观察

| 用例 | 判据 |
| --- | --- |
| `data_exhaustion_on_work_volume_never_claims_committed` | 数据填满后新内容上传第一块 → `507 INSUFFICIENT_STORAGE`；预上传内容提交时：要么 200 committed 且工作文件/版本都是完整新内容，要么 507/503 且工作文件=旧内容、版本数 1、操作行非 committed |
| `metadata_exhaustion_on_state_volume_never_reports_committed` | 元数据耗尽后提交 → 507/503、无 committed、无新版本；操作行 pending/rejected（可恢复/可解释）；工作文件只能是旧内容或已发布新内容 |
| `reflink_cow_allocation_failure_preserves_source_and_clone` | 正常克隆 `method=Ficlone`；耗尽后对克隆 `write_at` 真实 ENOSPC（errno 28）；克隆与源字节都不变；再次 `stage_copy` 失败原因属容量/IO 且不留下未验证暂存文件 |

## 限制

- 准入要求 Root 与内部状态同一 btrfs，因此“工作盘/状态盘”是两次独立 run 的独立 loop 卷，不是同一实例上的两块盘。
- 小文件内联/extent 布局是 btrfs 实现细节；用例以真实 ENOSPC（errno 28）为停点，不以写入量冒充。
