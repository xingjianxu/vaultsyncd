## 1. 接口决定

契约摘要见 `docs/architecture/interfaces.md`「外部移动、删除与挂载失效（S051）」。要点：

- **删除证据只有一种**：`ScanHealth::Complete`（完整且健康）的一轮扫描。扫描结论显式区分 `complete`/`permission_denied`/`io_error`/`mount_changed`，预算耗尽的“没走完”单列 `incomplete`；四类里只有第一类允许推导删除。为此 `WorkTreeError` 新增 `PermissionDenied`（与 `Unreadable` 分开），`InconclusiveReason` 的读失败带上 `ReadFailure` 分类。
- **移动只认文件对象身份**：`pair_moves` 用设备 + inode + 创建时间一对一配对，内容哈希不参与。两份同内容文件互换名字仍各保身份；同内容但 inode 不同不算移动；硬链接/一源多目标等歧义一律不猜。移动整轮持有 `RootCommitGate`，且必须在 `handle_files` 之前做——否则移动目标会被当成新文件建新条目。
- **互换名字不重绑，进复核**：两条路径都还在、文件对象换了位置时，一个单向移动表达不了（存储层会报目标被占），按路径重新采纳又会把两个 EntryId 绑到对方的文件上。选择保留双方基线、记 `identity_swap_needs_review`，既不删也不重绑。
- **异常批量缺失先保护**：`protection_reason` 按单轮上限（默认 32）与占比（默认 10%，已保护条目 <16 时只看数量）判定；命中整批进 `ProtectedBatch`，附原基线（路径/条目/revision/身份/内容）、父目录**实测身份**与计数；`release_protected(id)` 一次性放行（按路径 + 条目身份），队列满时逐个记 `held` 而不是丢弃。
- **挂载复核只有一条路**：`mounts::health::verify_root_mount`（卷身份 → 根目录身份/挂载 ID → 子挂载 → 可列目录），并接进 `RootHandle::verify`，于是 `LinuxWorkTree` 的每次枚举都复核。卸载后露出空目录 = `DirectoryChanged`/`MountChanged` = `ROOT_UNAVAILABLE`，整轮中止、零删除。
- **续扫也要用整轮快照**：一次完整扫描可能跨多轮续扫，核对用累计的 `scan_files`；只用本轮枚举到的文件会把别处已采纳的文件误判成删除（已按此修正并用“预算 1 → 多轮续扫”用例锁定）。

- `cargo test --locked -p vaultsyncd-server-core --lib` → 0，**305 passed / 0 failed**（原 265 + 6 纯规则 + 16 端到端 + 其它）。端到端覆盖：两份同内容文件改名后各保 EntryId、无新版本/新采集；同内容不同 inode 不配对（删除 + 新增，不串号，回收站保留旧版本）；完整健康扫描缺一个文件 → 一次删除事件与一次事件批次，下一轮不重复；**权限失败 / IO 失败 / 挂载变化（Root 不可用）/ 预算耗尽**四类都零删除且基线不动，权限恢复后同一候选才被提交；批量缺失进保护队列（原因、原基线、目录身份、计数）且复核放行后按同一身份传播；队列满 → `protection_queue_full`；存储失败与旧 revision 只 `held`；Root 忙整轮推迟；互换名字 → 两条 held、零删除、零重绑；线索驱动的 absent 不是删除。

## 4. 限制

1. **真实 `umount` 未执行**：需要特权挂载。验收用真实目录“改名 + 原路径建空目录”复现卸载后的现场（对根句柄而言与卸载等价），平台层另有真实目录的身份漂移/权限用例。真实卷/挂载组合留给 S103（文件与挂载故障集成验收）。
2. **移动/删除的存储适配未接**：`apply_external_move`/`apply_external_delete` 目前只有契约与 fake 实现，SQLx 适配、回收站落库、`changes` 事件内容属 S052 服务端整合闭环。
3. **目录级移动不识别**：`WorkTreePort` 只提供文件指纹；目录改名时其内文件按 inode 逐个保持身份，目录条目本身在库里仍按“新路径创建”，旧目录条目保留（不推导删除）。
4. **互换/被占目标需要人工处理**：`identity_swap_needs_review` 会一直保持到有人处理；这期间该路径不产生版本（保守方向，不会串身份）。
5. **保护队列在内存里**：进程重启后重新判定（不会误删，但复核决定需重做）；放行记录也是一次性的进程内状态。
6. 硬链接按独立条目处理（同一 inode 多路径会命中歧义分支，不做去重）。
7. 每个目录枚举都做一次完整挂载复核（`probe_path` + `mountinfo` + 一次 `getdents`），大目录树上开销不可忽略；需要时可按 Root 节流（未做）。
