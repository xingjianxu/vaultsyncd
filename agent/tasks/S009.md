## 1. 结果

- **新增交叉编译 devShell**：`flake.nix` 增加 `devShells.x86_64-linux.windows`（derivation `vaultsyncd-windows`），与 `default`/`quickemu` 同风格、互不影响。Nix 侧固定 rustup 1.29.2、cargo-xwin 0.23.1、clang/clang-cl 21.1.8、lld-link 21.1.8、llvm-lib 21.1.8、openssh、git，全部来自 `flake.lock` 的 nixpkgs rev `1d060086d60cb76a40cf37109f979d88a5bd6396`。
- **目标选 MSVC、不用 GNU**：`pkgsCross.mingwW64`（mingw-w64 14.0.0）导入库无 `libcldapi.a`，CFAPI 无法链接；xwin 下载的 Windows SDK 10.0.26100 含 `cldapi.lib` 与 `cfapi.h`（缓存内实测存在）。目标三元组固定 `x86_64-pc-windows-msvc`，只在 `tests/platform/windows/common.sh` 与 `rust-toolchain.toml` 各定义一次。
- **Rust 工具链来源与固定**：`rust-toolchain.toml` 改为 `channel = "1.99.0"` + `targets = ["x86_64-pc-windows-msvc"]`（原 `components` 已移除：Linux 的 rustfmt/clippy 由 nixpkgs 提供，交叉构建不需要）。rustup 按该文件安装官方 rustc 1.99.0（`b940084d7 2026-09-28`）与 rust-std 1.99.0 Windows 目标；NixOS 用 `nix-ld` 提供 `/lib64` 解释器，官方动态二进制可直接运行，无需 patchelf。
- **缓存不入库**：`RUSTUP_HOME`/`CARGO_HOME`/`XWIN_CACHE_DIR` 全部指向工作树根 `.cache/windows/`（新增 `.gitignore` 条目 `/.cache/`），不写 `~/.rustup`、`~/.cargo`。实测 rustup 1.7 GB + xwin 1.2 GB；`rm -rf .cache/windows` 可再生。
- **冒烟包**：新建 design §5.8 指定的 `tests/windows-integration/`（包 `vaultsyncd-windows-tests`，workspace `members`、**不在** `default-members`，`Cargo.lock` 已更新），两个零依赖 bin：
  - `platform-smoke`：`GetSystemInfo` 架构、`RtlGetVersion` 内核版本、`version.dll` 读 `version.dll`/`kernel32.dll` 的 `VS_FIXEDFILEINFO`。
  - `cfapi-link-smoke`：`#[link(name = "cldapi")]` 声明并调用 `CfGetPlatformInfo`，只读查询平台版本，用于保证 S010 不被链接/运行时解析问题卡住。
  - 两者在非 Windows 目标上只打印提示并退出 1，避免误跑 Linux 产物假装成功。
- **脚本**：`tests/platform/windows/` 下 `common.sh`（目标/包/产物/客体连接常量与 `guest_ssh`/`guest_scp`）、`setup-toolchain.sh`（幂等安装并复核工具链与标准库）、`build-cross.sh`（`cargo xwin build --release --locked`，产物复制到 `artifacts/windows/x86_64-pc-windows-msvc/` 并写 `SHA256SUMS`）、`run-on-guest.sh`（scp + 客体执行 + 两端哈希比对）、`guest-run.ps1`（客体内 `Get-FileHash` 与逐个执行，采集退出码）。
- **CRT 决策（本卡范围内）**：客体 `C:\Windows\System32` 只有 `vcruntime140_clr0400.dll`，没有 `VCRUNTIME140.dll`，动态 CRT 产物实测以 `-1073741515`（`0xC0000135` `STATUS_DLL_NOT_FOUND`）退出。`build-cross.sh` 因此导出 `RUSTFLAGS="-C target-feature=+crt-static"`，产物导入表只剩系统 DLL（`KERNEL32`/`ntdll`/`VERSION`/`cldapi`/`api-ms-win-core-synch-l1-2-0`），客体无需安装 VC++ 运行库。产品客户端的 CRT 部署方式留给打包卡决定，未在此固化。
- **文档**：`docs/operations/windows-lab.md` §12 重写为“宿主交叉编译 → 传输 → 客体原生执行”的可复现步骤（三条命令、工具链来源、CRT 说明、实测证据表），§14 增加 6 条交叉编译相关故障处理，§16 更新当前状态；`docs/environment.md` 新增 §13（分工、版本来源、devShell/脚本契约、客体运行证据、限制），并修正 §10.7、§12.1、§12.8 的过时表述；`docs/architecture/interfaces.md` 增加 `windows` devShell、缓存与清理、成员/lint 例外/`rust-toolchain.toml` 新契约，以及新增的 `tests/windows-integration` + `tests/platform/windows` 契约表；`README.md` 与 `AGENTS.md` 中“flake 尚未提供交叉工具链”的旧表述同步更新。
- **未改**：默认 devShell 包集合、quickemu shell、客体系统配置（只读检查了 `System32` 的 DLL 现状，未安装任何组件）。

## 3. 限制与未核验项

- 首次准备需要网络（rustup `static.rust-lang.org`、cargo-xwin `aka.ms/vs` + Microsoft manifest）；缓存共约 3 GB，未纳入仓库，也没有 CI 缓存策略。
- 静态 CRT 只对冒烟/测试产物生效；产品客户端与安装包的 CRT 部署方式、Tauri 壳与安装包签名的宿主支持属打包卡。
- 只在 `x86_64-linux` 宿主上验证；ARM64 宿主、Windows 原生构建、Wine 均未验证（Wine 也不能替代客体证据）。
- `platform-smoke`/`cfapi-link-smoke` 是直接 FFI 声明的最小冒烟，不是 `crates/platform-windows` 的正式适配层；CFAPI 注册、占位、回调与使用保护仍属 S010—S012，本卡不声称 CFAPI 已验证。
- 未验证：客体内 GUI/Explorer 集成、大文件传输耗时、`.cache/windows` 在 CI 上的复用方式。
- `agent/tasks/S003.md` 中“Windows 工具链由 S009 处理 / 不含交叉编译”属 S003 时点的历史表述，本卡不修改历史交接；当前能力以 `docs/environment.md` §13 为准，如需修订由档案整理任务统一处理。
