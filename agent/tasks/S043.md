## 1. 接口决定

- **一张会话行放两个摘要**：design §7.2 写一个 `token_digest`，但访问凭据与刷新凭据必须一起轮换，分行会让“刷新换掉了、访问还是旧的”。因此 `sessions` 有 `access_digest`/`refresh_digest` 两列（各 32 字节 SHA-256，各带唯一索引）与 `replaced_by` 自引用后继会话。design 的 `device_id` 改存登录提交的 `device_label`：首发没有设备注册表（design §17.1 也不加设备审批），不虚构设备身份。
- **凭据形态**：32 字节 OS 随机数的 64 位十六进制文本，库里只有摘要。`SecretToken` 的 `Debug`/`Display` 隐去内容，日志里只出现 `session_id` 与 `user_id`。
- **轮换的并发语义**：`rotate_refresh` 在同一个 `BEGIN IMMEDIATE` 事务里“带 `revoked_at IS NULL` 条件的 UPDATE 抢占旧行 → 插入后继 → 回填 `replaced_by`”。并发刷新只有一个成功，失败者得到 `Consumed`，核心映射成 `RefreshReused`（401）。**旧刷新凭据一律拒绝，不回放后继凭据**；“宽限窗口”或复用检测后撤销整条链需要产品决定，本卡不做。
- **到期判定在到期时刻即失效**（`<=`，不多给一秒）；判定顺序固定为“撤销 → 到期”，避免过期提示掩盖失效。
- **两种凭据载体，同一套会话**：`Authorization: Bearer` 供 agent/CLI，`vaultsyncd_session`/`vaultsyncd_refresh` cookie 供浏览器（`HttpOnly; Secure; SameSite=Strict`）。登录响应同时给出响应体凭据与 cookie，避免发明“客户端类型”头；刷新接受请求体或 refresh cookie。完整边界与代价见 `docs/adr/0001-auth-credential-carriers.md`。
- **CSRF 只针对 cookie 载体**：cookie 写请求要求 `Origin` 主机 == `Host`，或 `Sec-Fetch-Site ∈ {same-origin, none}`；都没有才按非浏览器客户端放行。Bearer 请求不判定（没有环境凭据可借）。失败 403 `ACCESS_DENIED`，不做“跨源 vs 缺头”的区分。
- **Root 授权**：`auth::scope::require_root_scope` 是纯规则；`apps/server::auth::authorize_root` 先 `roots::root_in_scope(conn, owner, root)` 取行——那次查询把“别人的 Root”和“不存在的 Root”压成同一个 `None`，因此 403 不泄露 Root 是否存在。`principal_from` + `authorize_root` 是后续资源端点的授权入口（I15）。
- **失败映射**：凭据问题 401 `AUTH_EXPIRED`；越权 403 `ACCESS_DENIED`；限流 429 `RATE_LIMITED` 带 `Retry-After`；存储/数据损坏 503 `NEEDS_RECOVERY` 并记日志（不伪装成“凭据过期”让客户端白刷）。
- **契约**：`api/openapi.yaml` 新增三个认证端点与 `LoginRequest`/`RefreshRequest`/`SessionIssued`/`SessionRevoked`；生成器 `format_version` 升到 3 并支持 `requestBody`（只接受 `application/json` + 具名 schema），TS 客户端为带请求体的端点生成 `body` 参数。浏览器刷新可省略请求体的路径由 ADR 说明（契约描述的是 agent 载体）。

## 4. 限制

- **没有浏览器侧实测**：cookie 属性、CSRF 判定与刷新路径只有单元/端点测试（`tower::oneshot`），没有真实浏览器与反向代理环境；`Origin` 与 `Host` 的比较假设代理保留原 `Host`（design §17.2 的部署要求）。
- **TS 产物未类型检查**：生成器改了 TS 客户端（`body` 参数、`payload` 变量、`content-type`），worktree 内无 `node_modules`，未跑 `pnpm typecheck`。
- **刷新契约与浏览器路径不完全一致**：`POST /v1/auth/refresh` 的请求体在契约里必填，浏览器走 cookie 时可省略；已在 ADR 与 interfaces 里写明，若要求严格统一需再动契约。
- **复用检测不撤销整条链**：旧刷新凭据被重放只拒绝本次，已签发的后继会话仍有效；链式撤销与宽限窗口需要产品决定。
- **限流仍是进程内、按登录名**：重启清零，不按来源地址（需要 HTTP 层与代理头策略）。
- **`users.status` 仍只有 `active`**：重置密码后失效全部会话（`sessions.user_id` 已有索引，但用例未实现）属后续账号管理卡。
- **按 URL 的凭据不接受**：只认 Bearer 头与 cookie。
