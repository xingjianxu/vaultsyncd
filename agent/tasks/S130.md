# S130 — 文件浏览器表格列与条目修改时间

状态：done。依据：用户要求文件浏览器列表 hover 不出现下划线、固定列宽（名称 50%，其余为大小/修改日期/操作）、大小改为
human readable，并明确选择“扩展服务端 modified_at”作为修改日期来源；design §7.2、§9.3、§18.1、§6、§9.4。

隔离：`/wrd/prj/vaultsyncd/.worktrees/S130-files-table`，分支 `feat/S130-files-table`，基线 `05b1ed2`（S129 已整合）。
主树干净，`.worktrees` 已忽略；无原生 worktree 工具，按 skill 用 `git worktree add`。devShell 基线
`cargo test -p vaultsyncd-server-store` 95 passed。

结果：
- 服务端此前没有任何按条目的时间：`revision` 只是计数，`changes.created_at` 是批次时间且无反向索引，
  `versions.created_seq` 只覆盖带内容的文件。新增迁移 `0014_entry_modified_at.sql` 给 `entries` 与
  `snapshot_entries` 各加可空 `modified_at`（UTC unix 秒）。
- 写入口记录同一批次的服务端时间：`entries::{insert_entry,move_entry,advance_entry_revision,restore_entry}`
  新增 `at: UtcTimestamp` 参数，`soft_delete_entry` 复用已有 `at`；调用方（commands、create_file、conflict_ops、
  executor、external、restore_ops、示例与测试装置）传入各自批次时间。合成根条目与升级前旧行保持 NULL，
  不用迁移时间冒充修改时间。
- 快照创建时把 `e.modified_at` 复制进 `snapshot_entries`，`server-store::snapshots::SnapshotEntry` 增加
  `modified: Option<UtcTimestamp>`；`api/openapi.yaml` 的 `SnapshotEntry.modified_at`（可选十进制文本）经
  `cargo xtask generate` 生成 Rust/TS DTO，`apps/server::sync::wire_entry` 映射为十进制秒。
- Web：列改为 名称 / 大小 / 修改日期 / 操作，去掉类型与修订号；`table-layout: fixed`，四列宽度份额
  50%/14%/24%/12%；名称单元格单行省略并带 `title`；链接 `underline="never"` 且 CSS 明确 hover/focus/active
  均无下划线；`fileSize` 改为 1024 进制人类可读（`1.5 KB`、`8 PB`、`0 B`，目录 `—`，未知 `未知`），属性面板
  另给 `fileSizeDetail`（人类可读 + 精确字节）并新增“修改日期”行；`fileModified` 按浏览器本地时区显示
  `YYYY-MM-DD HH:mm`，旧数据显示 `—`。

接口/入口：`docs/architecture/interfaces.md` 快照小节新增 “S130 修改时间” 条目；`docs/design.md` §7.2 `entries`
行补 `modified_at` 及“不是文件系统 mtime”的约束说明。迁移版本目标随之为 14。
