# S067-b — 真实暂存、取消与 Windows 验收

状态：实现完成，随父卡验证收口。`HydrationCallbacks` 的 fetch/cancel 只操作有限队列/取消信号，独立 worker runtime 等待网络和哈希。范围在完整版本校验后才 CfExecute；超时/取消/离线明确 NTSTATUS。取消须通过 `CancelableContent` 返回 S054 执行器，先保存已收到的块再退出；直接 drop 整份下载 future 会丢失尚未保存的进度，此接线已纠正。阶段记录与同步完成分离，本地保持 partial，后续真实扫描才证明完整驻留。

`files::staging::StagingFile` 在内部安全句柄目录中相对 no-follow 开/建单个普通文件，拒绝 reparse/占位/硬链接/重叠与外部写者；每块写后 sync，再更新 SQLite 位图。stage 按 Binding/Entry/Version 命名，重开 DB/连接仍核对同 pin。只允许清理可重建 stage，不改用户 dirty 数据。

原生 harness `tests/platform/windows/run-native-hydration.sh` 交叉编译 apps/agent 测试、传入现有 Windows 11 NTFS、比对 SHA-256；真实 localhost HTTP 固定版本服务与 CFAPI，非内容源替身。覆盖完整读取/head 改变、应用取消与重开库续传、503/损坏零供给、16MiB范围部分水合后逐字节补齐及复用已校验暂存。GENERIC_READ 打开会在 CreateFile 内整份水合；范围实验改用 FILE_READ_ATTRIBUTES 句柄，16MiB 样本区分范围与整份驻留。HTTP测试监听器在Windows会继承非阻塞状态，已显式切回阻塞；失败尝试不算通过。仅清理严格命名且 owner 已退出的本卡合成失败 run；保持VM在线。

OS CANCEL_FETCH_DATA 未能强制触发是继承的 S011 平台限制；本卡将真实回调路由接至相同取消 token，但不把应用显式取消证据冒充 OS 回调触发。实际数字与最终日志见 S067.md。连续范围保留最多16个已校验stage独占句柄，外部写无法修改；只释放句柄，不删除内容。未持同句柄的重启/未命中必须重新核对整份摘要。
