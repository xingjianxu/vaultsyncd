## 1. 接口决定

- **put 先核对已确认内容**（`apps/server/src/executor.rs`）：revision 基线通过后，用 `entries.content_version → versions.object_hash` 的摘要比对工作目录实测摘要；不一致或外部删除尚未采纳时，登记 rejected 并返回 `409 RECONCILE_REQUIRED`，不写意图、不发布。修掉了“外部写入尚未被观察循环采纳时，客户端旧基线静默覆盖未采集内容”的真实数据丢失路径；观察采纳后按新 revision 重试即可提交。契约详见 `docs/architecture/interfaces.md`「S103 — 文件与挂载故障集成验收」。
- **Root 内 symlink 的既有语义保持不变**：扫描把它记为 `UnsupportedKind`（skipped）→ 采集显式 `blocked`，不跟随、不采纳、零删除；本轮补了真实服务进程与 Windows 原生证据。
- **重新挂载后仍保持 `ROOT_UNAVAILABLE`**：健康复核比较挂载 ID，remount 会产生新 ID。本轮确认这是保守暂停（零删除、零采纳），恢复写入需重新准入/注册；未在本卡放宽。

## 4. 失败与修复

1. 首轮真实用例证明 T18 缺陷：外部写入未被采纳时 put 返回 200 committed，外部字节从未成为版本（数据丢失）。修复为“已确认内容前提 + RECONCILE_REQUIRED”，补 5 项集成用例，全仓回归通过。
2. 挂载用例首版把内部状态放在主机文件系统、Root 放在 loop：被准入正确拒绝（`internal_state_other_filesystem`）。改为状态与 Root 同卷、Root 为子卷真实挂载。
3. `umount` 因服务持有 Root 句柄 EBUSY：按管理员实际操作使用 `umount -l`（仍在自建卷上），记录为真实卸载手段。
4. `sudo` 选项顺序导致 `--bind` 被当作 sudo 参数：改为 `sudo -n mount --bind ...`。
5. 首版元数据填充量不足（put 仍成功）：改为内联小文件 + 数据填满阻止新元数据块，直到真实 ENOSPC，再断言失败语义。

## 5. 限制

- remount/子卷替换后 Root 仍 `ROOT_UNAVAILABLE`（mount id 漂移），需要重新准入；本卡只确认期间零删除/零采纳，未改产品恢复流程。
- 一张 Windows 客体、顺序执行；不冒充多机并发。Windows 全套中 IPC ACL 用例依赖独立测试本地用户，本次以过滤矩阵取证。
- T21 的“工作盘/状态盘”是两次独立 run 的独立 loop 卷（准入要求 Root 与内部状态同一 btrfs），不是同一实例上的两块盘。
- 外部非协作写入的瞬态仍不保证逐次保留（design §12.2）；用例只断言完整采集内容与最终稳定内容。
