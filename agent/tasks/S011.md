## 1. 结果

- **`cfapi::content`（新，纯逻辑、宿主可测）**：固定内容源 `CONTENT_SEED` + 条目名派生位置块（SplitMix64），因此内容与版本固定、可随机区间生成（区间字节 == 整份切片）；`entry_for_path` 只认 `…\vaultsyncd-proto\<固定条目>`；`check_range` 拒绝负偏移/非正长度/越界；`expected_digest` 给整份 SHA-256；**自带 SHA-256**（NIST 向量锁定，含 1,000,000×`a`）；`serve_range` + `ChunkSink` 是回填循环本身：每段前查取消、下游拒绝即停、非法范围在发送前失败。
- **`cfapi::provider`（新，仅 Windows）**：`ProviderConfig`（`available`/`unavailable`、`latency_ms`、`timeout_ms`、`chunk_delay_ms`）、`ProviderStats`（fetch/chunk/bytes/range_rejections/cancel_callbacks/aborted/timeout/unavailable/failed_acks/peak&in_flight）、进程级 `OnceLock<Arc<ProviderContext>>` 上下文（回调**不解引用** `CallbackContext` 裸指针 ⇒ 结构上不存在“访问已释放状态”；断开后 `wait_idle` 确认无在途回调）、`FETCH_DATA` 分段 `CfExecute(TRANSFER_DATA)`、`CANCEL_FETCH_DATA` 置 `TransferKey` 取消标志、`ProviderSession`（连接/断开/静默）。

## 3. 阻塞与限制

- **`CANCEL_FETCH_DATA` 未观察到（本卡唯一未达成项）**。5 条路径全部实测：① `CancelSynchronousIo(读线程)` 返回成功但水合继续完成；② `CancelIoEx(文件句柄)` = `ERROR_NOT_FOUND`(1168)；③ 传输中关句柄 ⇒ `CfHydratePlaceholder` 立刻返回但平台仍索取全部 17/17 段；④ 传输中 `CfDisconnectSyncRoot` ⇒ 在途分段被拒、循环立即停止，但平台没有发 cancel 回调；⑤ 跨进程请求（PowerShell 读取、`--no-connect` 的 hydrate）提供方**完全收不到 `FETCH_DATA`**，请求方一直阻塞。恢复条件：找到本 build/卷上真正触发 `CANCEL_FETCH_DATA` 的操作（例如换卷/换 build，或打通跨进程唤醒后用“杀掉请求进程”），届时 `run-cancel` 用 `--require-cancel-callback` 严格断言即可；代码路径（原子取消标志 + `serve_range` 每段检查）已实现并由宿主单测覆盖。
- **跨进程提供方唤醒未打通**：其它进程读同一同步根时连接持有进程收不到 `FETCH_DATA`，请求方阻塞。本卡的取消/中断验证因此都在同一进程内完成，不据此声称多进程可用。
- 打开带读权限的占位符会触发**整份**水合并阻塞（`open_ms≈993`，1 MiB + 60 ms/段），`FULL` 与 `PARTIAL` 策略在本 build 表现一致；真正的范围请求只能用 `CfHydratePlaceholder` 取得。
- 内容源是原型用的确定性固定版本，没有 `entry_id + version_id` 绑定、没有块级 + 整文件二阶段校验，不代表 design §13.1/§13.2 的完整下载语义。
- 只在 `C:` 卷 NTFS、build 26300 上实测；ReFS、非系统卷、Explorer 展示未验证。产物不逐字节可复现（MSVC 调试签名），验收用当次两端哈希。
