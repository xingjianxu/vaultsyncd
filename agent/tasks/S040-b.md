## 1. 接口决定

- **单条目与子树是同一条路径**：`restore_trash` 不再分“目录/文件”两套流程，而是把清单映射成
  `Vec<PlannedEntry>` 后统一处理——单条目就是长度为 1 的子树，避免两套顺序各自演化。
- **规划是纯计算，先于任何 I/O 与 `pending` 登记**：`plan_subtree(subtree, root_path)` 把清单映射到
  新位置并按（路径深度, 路径）排序。根用调用方决定的实际路径（可能已另名），后代一律“根新路径 +
  清单相对后缀”，因此另名只改变位置前缀、不改子树内部结构。结构不一致一律
  `store_contract_violation`（wire `NEEDS_RECOVERY`）停写：后代不在根路径之下、同一条目出现两次、
  两个条目落到同一路径、父目录不在清单里、父目录是文件、普通文件带后代。任一行过期 →
  `version_gone`。这些都在写 `pending` 与动磁盘之前完成，坏清单不会留下一条卡住同一 `OpId` 的记录。
- **服务端派生意图身份与暂存名**（父卡限制第 4 条）：
  - `intent_for(seed, index)`：第 0 个文件就是请求里的 `intent_seed`，其后把种子最后 8 字节当大端
    u64 递增；同一操作内互不相同，同一 `OpId` 重试（同一清单、同一顺序）得到同一组身份，溢出报
    `invalid_request` 而不回绕到别的操作的身份上。请求字段因此由 `intent_id` 改名为 `intent_seed`。
  - `staging_name(intent)` = `.restore-<意图十六进制>`：由意图身份派生而不是客户端给，稳定、可重入、
    操作内互不相同、形态是单个文件名。`TrashRestoreRequest` 因此删掉 `staging_path`。
- **顺序**：按深度把目录 `mkdir` 回来（`inspect` 必须 `Absent`，已存在按 `SUBTREE_CHANGED` 停写，
  不把清单内容合并进别人的目录），再逐个文件“内容租约 → 现场空缺 → 意图 `prepared` → 发布 →
  `published`”；每个文件一个意图、一个暂存名、一个租约（用途 `download`，到期 `at + 900`）。
- **单一事务**：整棵子树清软删除、改回父目录与名称、推进 revision、删清单行、事件批次、操作结果与
  `intents` 一次收尾（`TrashRestoreWrite::intents`/`entries` 本就按多条目设计，无需改端口）。
- **失败即整批停下、不部分提交**：任一建目录/租约/观察/发布/事务失败都返回
  `RestoreFailure`（`is_committed()` 恒 `false`），元数据事务从未开始；底层稳定码原样保留
  （`no_space`、`reconcile_required`、`store_contract_violation`、`subtree_changed` 等），
  并带 `intent_id`/`phase` 说明停在哪条意图的哪个阶段。已建目录、已发布文件与已持久化意图留作
  `fs_intents` 恢复证据；旧条目与内容对象一字未动（不删、不改引用）。
- **租约在成功与失败路径都解除**：`history::release_after_failure` 改为整批切片，新增
  `history::release_all`（成功路径，未解除时报告最晚保护时刻）。顺带修掉两处同缺陷：事务证据不符
  （含新增的条目数核对）与历史版本恢复的证据不符路径原本会遗留租约。

## 4. 限制

- **真实适配器仍未落地**：`TrashRestoreStore`/`ContentLeasePort` 的 SQLx 实现与进程内装配未写
  （与 S035/S039/S040 同一缺口）。“旧版本字节与行不变”在回收站一侧由“事务只清软删除/改位置、不写
  `versions`/`objects`”的端口契约保证，真实库用例属装配卡。wire 端点（Restore 命令、
  `GET .../versions`）同样属装配/端点卡。
- **中止后的现场要协调，不能盲目重试**：中途失败会留下已建目录与已发布文件（恢复证据，但元数据未
  认领）。同一 `OpId` 再试只会得到 `operation_pending`（`NEEDS_RECOVERY`）；换新 `OpId` 重试时目标
  目录已存在，会按 `SUBTREE_CHANGED` 停写等协调。收尾/清理属启动恢复卡，不在假端口范围。
- **另名只作用于根**：后代保持清单里的名称；若某个后代的名称在此期间被同父项下的活跃条目占用，事务
  内的 `NameOccupied` 会让整批失败（不覆盖），不会逐个另名。
- **另名规则不截断**：沿用 S040，超长名称会 `validate_name` 失败并逐个跳过，最坏
  `restore_name_unavailable`。
- **`intent_for` 是顺序派生**：意图身份按“文件在（深度, 路径）顺序里的序号”派生，因此依赖
  `trash_subtree` 返回稳定的清单顺序；清单在两次尝试之间变化的场景由 `pending` 记录挡住，不做跨清单
  的身份迁移。
