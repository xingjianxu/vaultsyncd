## 失败与修复（证据全部保留，未改写为成功）

1. native-1/2：本 run 卷未就绪、目录权限不足（已用专属 loop 卷 + 0700 修正）。
2. native-3：测试控制请求被产品严格 capabilities 门拒绝——改独立、校验证书、不带凭据的测试控制 client，产品门未放宽。
3. native-5/6/7：真实暴露两处产品装配缺口——HTTP SSE 订阅缺失、scheduler/恢复上传未做 epoch/changes 准入。native-5 的“无隔离/无重建日志”作为缺陷前证据保留；native-7 后六项稳定通过。
4. `native-outage`（`ad74645`）：新增快照断网后 T15 有 3 项转红。根因是真实产品缺陷：重建日志因拉快照断网停在未完成，下次装配时 `ControlledApply::recover`/`Release::recover` 的 `ensure_unblocked` 直接拒绝，导致准入永远无法续接日志（永久 NEEDS_RECOVERY）。修复 `1095f38`：新增 `recovery::resync::rebuild_open`，装配遇到开放重建时跳过旧 apply/release 启动恢复、继续装配，把续接交给准入；围栏与隔离不变。日志 `artifacts/S102/native-outage.{log,exit}`、报告 `artifacts/S102/e2e-1794018716-655667/report.json`。
5. `native-clean-1`：漏配 `VAULTSYNCD_RELEASE_SERVER`，误用 S074 helper，报“服务端缺少路径 dirty.txt”（基础设施/命令错误，非产品）。补齐 helper 与 `VAULTSYNCD_*` 环境后 `native-clean-2` 六项全过。
