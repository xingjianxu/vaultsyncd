# S065-a — Windows 安全句柄与元数据扫描

状态：done；父卡 S065 的文件边界部分。为控制单卡源码落点，监视/原生验收另记 S065-b。

`files/{mod,native}.rs`：`RootHandle::open/verify/inspect/scan/overlaps` 用卷 serial+128 位 FileId 识别对象。每一分量由 `NtCreateFile(RootDirectory=已持有句柄)`、no-follow/no-recall 打开；未知 reparse、junction/symlink、跨卷、非法名及过长路径明确失败。目录元数据用 `GetFileInformationByHandleEx` 从句柄枚举，迭代补扫避免深层递归持有二次方数量的句柄。硬链接、碰撞、权限/局部错误保留为问题，整轮禁止缺失推导。`CfGetPlaceholderInfo` 提供驻留/dirty/pin/identity，避免相信被过滤器隐藏的 reparse 属性。

本机 Windows 11 NTFS 原生证明：已 pin 的空目录经真正 `FSCTL_SET_REPARSE_POINT` 变 junction 后，root-relative 子项打开拒绝，外部内容未变；盘符别名仍识别同一目录；大小写/Unicode、>260 字符路径与非法/保留名均按预期。新 ACL 必须用无 backup intent 的 root-relative 重开核对；已有句柄或 Win32 backup 语义不能作权限仍健康的证据。最终命令、测试数、hash 与工作树续接见 S065。
