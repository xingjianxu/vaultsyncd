## 1. 结果

- 根 `Cargo.toml` 为虚拟 workspace：`[workspace]` 带 `resolver = "3"`，`members`/`default-members` 只含真实存在的 `crates/domain`，不预建空 crate。
- `crates/domain` 包名 `vaultsyncd-domain`（design §5.4 职责：身份、条目、版本、操作、错误与业务不变量，不做 I/O）。`src/lib.rs` 只有 crate 文档（职责边界、不做 I/O、外部事实由调用方传入、后续卡 S015/S016 才落地类型）与 `#![forbid(unsafe_code)]`，不写占位 API/TODO。
- `[workspace.package]`：`edition = "2024"`、`rust-version = "1.85.0"`、`version = "0.1.0"`、`publish = false`；crate 侧全部用 `.workspace = true` 继承，并以 `[lints] workspace = true` 接入公共 lint。
- 公共 lint：`[workspace.lints.rust]` `unsafe_code`/`missing_docs`/`unused` = deny；`[workspace.lints.clippy]` `all = { level = "deny", priority = -1 }`。
- `rust-toolchain.toml`：`channel = "1.99.0"`、组件 `rustfmt`/`clippy`。Linux 由 `nix develop` 提供同版本、不读该文件；Windows 由 S009 用 `rustup toolchain install 1.99.0-x86_64-pc-windows-msvc` 取同一版本，两端不漂移。本卡实测 `nix develop -c rustc --version` 输出 `rustc 1.99.0 (b940084d7 2026-09-28)`，与 channel 完全一致；`rustfmt 1.10.0`、`clippy 0.1.99`。
- `rustfmt.toml` 只固定 `style_edition = "2024"`，与 workspace edition 对齐；`cargo fmt --check` 可执行。
- `.gitignore` 最小补充 `/result`、`/result-*`（flake 已在仓库根，`nix build` 会生成输出符号链接）；已有的 `/target/`、`**/target/`、`/artifacts/`、`/var/`、`.worktrees/` 不动，`Cargo.lock` 显式未忽略。
- `Cargo.lock` 由 `cargo generate-lockfile` 生成（lockfile `version = 4`），提交入库；无第三方依赖。

## 2. 版本决定

edition 2024 + resolver 3 + `rust-version = "1.85.0"`：edition 2024 在 1.85.0 稳定（`docs/environment.md` §10.4），resolver 3 是 edition 2024 的默认解析器，因此 1.85.0 是本组合的可声明下界。实测：`cargo metadata` 报 `edition: "2024"`、`rust_version: "1.85.0"`；`cargo check --locked` 在 1.99.0 上退出 0（cargo 自身会按 rust-version 校验工具链）。限制：devShell 内无 1.85.0 工具链（不引 rustup），未在 1.85.0 上真编译；该下界属声明值，Windows/CI 侧的 MSRV 复核留待 S006/S009。

## 3. 验证（全部在 `nix develop -c` 内真实执行）

- `cargo generate-lockfile` 退出 0；`cargo metadata --locked --no-deps` 退出 0，`workspace_members` 与 `workspace_default_members` 都只有 `vaultsyncd-domain@0.1.0`，target 仅 `lib`。
- `cargo check --locked` 0；`cargo fmt --check` 0（`--verbose` 确认读取 `rustfmt.toml`、`style_edition = "2024"`）；`cargo clippy --locked --all-targets -- -D warnings` 0（实检 lib target，非空跑）；`cargo test --locked` 0（0 tests，含 doc-test 0）。
- 负控 1（格式）：临时追加未格式化函数后 `cargo fmt --check` 退出 1 并输出 `Diff in …lib.rs`；还原后退出 0，文件与干净副本逐字节一致。
- 负控 2（lint）：临时加 `unsafe {}` 后 `cargo check` 退出 101，诊断指明 `#![forbid(unsafe_code)]`，另 `-D dead-code` 由 `-D unused` 蕴含，证明 workspace lint 生效；还原后退出 0。
- 负控 3（clippy）：临时加 `a + b + 0` 后仅跑 `cargo clippy`（不加 `-D warnings`）即退出 101，报 `-D clippy::identity-op implied by -D clippy::all`，证明 `[workspace.lints.clippy]` 表格接线正确；还原后 `-D warnings` 退出 0。
- `find . -name Cargo.lock -not -path './target/*'` 只有 `./Cargo.lock`；`git diff --check` 无输出；无 `result*` 符号链接；`target/` 由 `.gitignore` 忽略且未入库。
