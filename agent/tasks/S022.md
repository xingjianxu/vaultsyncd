## 1. 接口决定

- **两个新模块，不新建 crate**：`crates/planner/src/rename.rs`（design §9.5、§10.1 移动行、跨 Root 两段任务）与 `delete.rs`（design §10.1 删除行、§10.3 子树前提）。仍是纯规则：不枚举同级条目、不读时钟、不分配身份、不做 I/O。
- **`rename::plan_move(&MoveRequest) -> Result<MoveOutcome, MoveError>`**：输入 `base`/`local`/`remote` 三方事实（已绑定同一 `EntryId`）、`targets: MoveTargets { local, server }`、`late: Option<&LateBranch>`。输出 `MoveOutcome::Planned(Box<MovePlan { main: Plan, late: Option<ConflictCopy> }>)` 或 `MoveOutcome::Replan(ReplanReason)`。
  - 分支：仅远端移动 → `ApplyRemoteMove`（内容未变不带 `DownloadVersion`，T09）；仅本地移动 → `UploadMove`（纯移动）或 `UploadMoveWithContent`（移动+修改，带 `SnapshotLocalContent`）；同位置同内容 → `MergeSameResult`；双方都变且结果不同 → 主条目保留已提交侧 + `late` 冲突副本。
  - **`EntryId` 不随路径变**：所有主条目动作携带基线身份；只有迟到分支拿新冲突身份。跨 Root 是明确例外（design §9.5），走 `plan_cross_root_move`。
  - **迟到分支命名**：意图位置与主条目相同时才用 §10.2 冲突名（`conflict_entry_path`），不同则保留用户选定的名称；单侧移动不需要冲突身份，缺失时返回 `MoveError::LateBranchMissing` 而不是默认成功。
  - **前提不成立给重规划结果**：`ReplanReason::{DirectoryCycle, TargetOccupied, TargetAncestorMissing, IdentityReplaced, DirectoryConflictRequired}`。目标位置观察由调用方传入（`TargetState::{Vacant, Occupied, AncestorMissing}`）；目录环按路径分量判定（`docs` 与 `docs-old` 无关）。
- **跨 Root：`plan_cross_root_move(&CrossRootMoveRequest) -> Result<CrossRootOutcome, MoveError>`**：`create_target`（`UploadNewEntry`，前提含 `ServerPathVacant`）与 `delete_source`（`DeleteEntry`，带源修订与目录子树 token）两段；**`delete_source` 必带 `Dependency::CrossRootTargetCommitted`**，目标创建失败或结果未知时源删除不得计划完成（本卡验收）。源与目标 Root 相同返回 `MoveError::SameRoot`。
- **`delete::plan_delete(&DeleteRequest) -> Result<DeleteOutcome, DeleteError>`**：`DeleteOutcome::{Upload, ApplyLocally, Preserve, AlreadyDeleted, ConflictRequired, Replan}`。
  - 远端仍是基线修订 → `Upload`（`DeleteEntry`，目录必须带 `SubtreeToken`，文件带 token 是错误）；`subtree_changed` → `Replan(SubtreeChanged)`（T12，`SUBTREE_CHANGED`），绝不吞掉并发新增子项。
  - 远端修订已前进 → 内容变了 `ConflictRequired(ContentModified)`（旧 Delete 不删新内容）、只移动了 `ConflictRequired(Moved)`、形状不变 `Replan(BaseRevisionMismatch)`。
  - 远端已提交删除 → 本地已无条目 `AlreadyDeleted`（同一修订幂等成功）、本地未变 `ApplyLocally`、本地已修改/已移走 `Preserve`（T11：恢复冲突条目先提交，主计划才撤旧身份；移动情形保留用户选的位置）。
  - **新类型 `delete::SubtreeToken`**：服务端生成的不透明 16 字节值（`from_bytes`/`as_bytes`，只比较相等）；首发固定 16 字节，长度变化属于协议契约变化。
- **`reconcile::Action` 扩充 5 个变体**（`ApplyRemoteMove`、`UploadMove`、`UploadMoveWithContent`、`ApplyRemoteDelete`、`DeleteEntry`）、`Dependency` 增 `CrossRootTargetCommitted`；因动作携带 `RelativePath`/token，**`Action` 改为只 `Clone` 不 `Copy`**（`Plan` 本来就只 `Clone`）。`reconcile` 遇到这些输入仍只给 `Defer(MissingEntry)`/`Defer(LocationOrKindChanged)` 作为转交信号，不抢裁决。
- **复用而非复制**：`conflict::create_copy_plan` 增加“目标位置为空”形态（`head: None` → `ServerPathVacant` 前提），供移动迟到分支与删除恢复条目共用；`reconcile::merge_same_result` 改 `pub(crate)` 供移动归并复用。

## 4. 限制

- 每个条目一份计划，不枚举同级条目、不检查父目录存在性、也不做子树遍历：目标位置是否为空/祖先是否在由调用方观察后以 `TargetState` 传入，执行器仍须用 `Prerequisite::TargetPathUsable`/`ServerPathVacant` 在执行前复核并按结果重新规划。
- 目录的并发移动（迟到分支是目录）只给 `Replan(DirectoryConflictRequired)`，目录冲突记录与目录子树保留（删除侧 `DirectoryPreserveRequired`）要等目录级执行器卡（S038/S039）；本卡不假装一份文件副本能表达子树。
- 删除与修改/移动的裁决按“已提交侧为主 + 保留迟到内容”实现；`ConflictRequired` 的实际冲突呈现（冲突清单、用户选择）归 agent-core 与服务端接口卡（S036/S047）。
- `SubtreeToken` 首发固定 16 字节且只支持相等比较；服务端生成规则、wire 编码与 `SUBTREE_CHANGED` 的返回在 S028/S038/S047 落地时需与本节契约对齐（长度变化要同步 `api/`）。
- `Action` 不再 `Copy`：下游执行器/接口代码若之前按值复制动作需改 `clone()`（当前仓库无此类消费者）。
- 恢复冲突条目与迟到分支的路径由 planner 生成，但“同名是否已被占用”只能执行时核验；撞名需执行器用 `ShortIdLen::extended` 重新规划（沿用 S021 的边界）。
