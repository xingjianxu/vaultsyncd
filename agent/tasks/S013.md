## 1. 结果与接口决定

- 新增 `crates/platform-linux-server`（包 `vaultsyncd-platform-linux-server`，members 非 default-members，**无第三方依赖**）。内核 ABI 只在 `mounts/raw.rs` 最小声明（`fstatfs`/`statx`/`ioctl` + `FS_IOC_GETFLAGS`/`BTRFS_IOC_FS_INFO`/`BTRFS_IOC_INO_LOOKUP` 三个只读请求），`struct statfs`/`struct statx`/两个 btrfs 结构都用 `size_of`/`offset_of` const 断言锁住 LP64 布局；未声明任何设置标志、清 NOCOW 或改挂载的调用。
- **lint 偏离说明**：包级 `unsafe_code = "allow"`（省略 `[lints] workspace`、手抄其余 lint），与 S010 `crates/platform-windows` 同一写法。原因是语义要求：`fstatfs`/`statx`/ioctl 必然 unsafe，而在继承 workspace lint 的包内无法单独放行。
- 模块：`raw`（FFI）、`mountinfo`（`/proc/self/mountinfo` 解析）、`paths`（按分量判关系）、`probe`（打开 `O_PATH`+`O_RDONLY` 双句柄、核对 inode 未变、读事实、遍历目录）、`admission`（纯逻辑判定）、`content`（稀疏≠占位）。
- **未依赖 libc**：只用到 5 个符号，自声明 + const 断言比新增依赖更小且离线可构建。
- 子卷 ID 来源优先级：`statx(STATX_SUBVOL)`（内核 6.7+，无需特权）→ `BTRFS_IOC_INO_LOOKUP`（需 `CAP_SYS_ADMIN`）→ mountinfo `subvolid=`（仅目录本身是挂载点时）；FSID 用 `BTRFS_IOC_FS_INFO`（非 root 可用）。身份 = `(FSID, 子卷 ID)`，目录身份再加 inode；**不用设备号**——实测 btrfs 每子卷匿名设备号与 mountinfo 后端设备不同。
- 拒绝原因有稳定 `code()` 与设计错误码：后端非 btrfs（FUSE/NFS/CIFS/overlay/tmpfs/ext4/xfs/zfs）、子卷身份不可得、NOCOW 标志、`nodatacow`/`nodatasum` 选项、嵌套子卷、子挂载、内部状态目录重叠/非 btrfs/跨文件系统、已注册 Root 的别名与路径重叠，全部映射 `UNSUPPORTED_STORAGE_BACKEND`；`verify_unchanged` 的漂移映射 `ROOT_UNAVAILABLE`。扫描被上限截断时给 `decision=inconclusive`（退出码 4），不当作通过。

## 4. 限制

FUSE/NFS/SMB 无真实挂载样本（缺 FUSE daemon 与 NFS/SMB 导出），只由单测覆盖分类；扫描默认上限 20000 条目/32 层，超出即 inconclusive；遍历只对目录查 NOCOW 标志，文件级由 `content` 子命令/后续扫描器负责；无 `STATX_SUBVOL` 的旧内核需 `CAP_SYS_ADMIN` 才能取子卷 ID（Ubuntu 24.04 未实测）；Linux 无统一第三方占位判定，`SERVER_PLACEHOLDER_UNSUPPORTED` 不自动产生；本 crate 不在 default-members，`cargo xtask check`/CI 不构建它（`cargo xtask check` 本轮因 worktree 无 `node_modules` 未完整跑，Rust 四步已单独执行通过）。
