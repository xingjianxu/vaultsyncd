## 1. 接口决定

- 落点：`crates/server-core/src/observer/{scan,capture,import}.rs`（卡面写的 `scan.rs` 落实为枚举与稳定窗口，采集/采纳与轮次编排各自成文件）；端口 `ports/{work_tree,external_store}.rs`；`objects::capture_observed_object`；Linux 适配 `apps/server/src/observer.rs`（平台库不依赖核心，装配在进程入口，与 S033 示例同一原则）。契约摘要见 `docs/architecture/interfaces.md`「外部目录初始稳定采集（S049）」。
- **扫描有上限且诚实**：预算耗尽、目录/项读不了、Root 不可用都返回 `ScanCompletion::Inconclusive{resume, reasons}`；续扫游标可在目录中途精确继续（`after` + 失败项 `retry`）；枚举**从不产生删除结论**；并发消失单列 `Gone`/`Absent`。符号链接/特殊文件/非 UTF-8 名进 `skipped`。
- **稳定性不以 mtime 为准**：指纹含 inode/btime/大小/ctime/链接数；首次看到总等待完整窗口；保留 mtime 的改写靠 ctime 发现。
- **采集前后核对 + 采纳前再核对**；候选长度不等于建副本前的源长度（复制期间增长）→ 重排队；任何指纹变化 → 重排队并重新计时。克隆原子性只当“相对并发写原子的字节副本”，不当“应用已保存完成”（模块文档与测试名写明；`unobserved_transient_content_is_not_claimed_as_preserved`）。
- **采纳不写工作目录**（内容已在那里）：与 put 共用 `RootCommitGate`，一个 `ExternalAdoptStore::apply_external` 事务写对象登记/版本/revision/事件批次；库里内容相同不产生版本；证据不符按契约违反，不当成已采纳。
- **“首次未采集成功不标已保护”**：`ExternalObserver::history_protected` 仅在采纳成功（或库里已有相同内容）后为真；`initial_import_complete` 需完整扫描 + 当时无待处理，且只增不减。
- **复查待处理文件**：续扫只覆盖游标内目录，因此每轮对“仍待处理但本轮没扫到”的文件单独 `observe`（受扫描预算限制），避免一个永远读不了的目录让其他文件的稳定窗口停滞。

## 4. 限制

1. **真实存储适配未落地**：`ExternalAdoptStore`/`PutCommitStore` 只有测试假实现；`roots.pending_import` 仍是注册时常量，`initial_import_complete` 未落库（S044 限制 3 遗留，需 `roots` 迁移，宜与存储适配一起做）。
2. **没有后台调度**：`ExternalObserver::run_pass` 由调用方驱动；`apps/server` 尚未按 Root 启动周期轮次，也无 inotify/溢出补扫（S050）。
3. 已采纳文件的外部删除/改名事件管线、冲突保留（检测到重叠写入时暂停覆盖）不在本卡。
4. 内核时间戳粒度约数毫秒：极短间隔内相同大小的两次写入可能得到相同 ctime，指纹无法区分——这正是 C33 的边界，真实用例因此在写入间留 25 ms；本卡不声称更长窗口能解决。
5. 放弃采纳（指纹变化）后已发布的候选对象成为无引用对象，依赖后续对象 GC。
6. 账本仅进程内；`pending` 随文件数增长（受 `max_entries` 与整树大小约束，未设上限）。
7. 适配器 `LinuxObjectPort` 与 `examples/object-capture.rs` 的同名类型有重复实现（平台库不依赖核心，无法共享）。
