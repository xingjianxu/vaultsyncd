## 1. 结果

- 根 `package.json`：`private: true`，`packageManager`、`engines.node`、`engines.pnpm` 三重锁定 devShell 实测版本（pnpm 12.9.0 / node 24.21.0）。不追“最新”：版本源是 `flake.lock` 固定的 nixpkgs，改版本必须先改 flake 输入，因此不会在两次 `pnpm install` 之间漂移；corepack/pnpm 12 若见到不同版本会直接报错而非静默升级。
- 根脚本 `typecheck` = `pnpm --recursive run typecheck`，覆盖全部已创建成员；根 `devDependencies` 只有 `typescript 7.0.2`（pnpm 脚本自动把根 `node_modules/.bin` 加入 PATH，因此成员脚本无需各自安装 tsc）。
- `pnpm-workspace.yaml` 只列 `packages/ui`，不为尚未创建的 `apps/web`、`apps/desktop`、`packages/api-client`、`packages/local-ipc-types` 预留占位。
- `packages/ui`：包名 `@vaultsyncd/ui`（design §5.6 的前端公共包），`private: true`，`exports` 直接指向 `./src/index.ts`（本卡无构建步骤，不产生 `dist/`）；`tsconfig.json` 只写 `extends: "../../tsconfig.base.json"` 与 `include: ["src"]`。
- 导出（无平台 I/O，符合 §5.6 与 §6 边界）：`StatusBadge` 纯展示组件 + `StatusBadgeProps`、`StatusTone` 两个类型。它不读文件、不发请求、不持有状态；同步状态与拒绝原因仍由 Rust 纯核心（§7）定义，应用层映射成 tone 后传入文案。
- 根 `tsconfig.base.json`：`strict`、target/lib ES2022 + DOM、`module: ESNext`、`moduleResolution: bundler`、`jsx: react-jsx`、`esModuleInterop`、`isolatedModules`、`skipLibCheck`。未放 `outDir`/`declaration` 等只在真正引入构建时才需要的东西。
- 依赖最小集：react 19.3.1、react-dom 19.3.1（同时以 `peerDependencies` 声明，应用自带运行时）、`@types/react` 19.3.0、`@types/react-dom` 19.3.0、typescript 7.0.2。选 TypeScript 7 是因为 registry 当前稳定版即 7.0.2（带平台原生二进制包 `@typescript/typescript-linux-x64`），与 19.x React 类型实测通过；不额外引入 bundler、测试运行器或 lint，留给 S076/S006。

## 2. 验证（全部在 `nix develop -c` 内真实执行）

- `pnpm install`：退出码 0，输出 `Scope: all 2 workspace projects`、`Done in 9.5s using pnpm v12.9.0`，新增 8 个包；registry 命中 `https://registry.npmmirror.com`（用户 `~/.npmrc` 指定，`curl` 探测返回 200、0.65s），store 落在 `/wrd/.pnpm-store/v11`（pnpm 提示 home store 无法跨文件系统硬链接，属预期）。首轮 `pnpm-lock.yaml` 440 行：第一个 YAML 文档是 pnpm 12 的 `packageManagerDependencies`（各平台 `@pnpm/exe.*` 12.9.0），第二个才是常规 `lockfileVersion: '9.0'` 依赖图。
- `pnpm install --frozen-lockfile`：退出码 0，`Lockfile is up to date, resolution step is skipped`、`Done in 12ms`，不改写 lockfile。
- `pnpm --filter @vaultsyncd/ui typecheck`：退出码 0（`tsc --noEmit` 无诊断）；根 `pnpm typecheck`：退出码 0，实跑成员 typecheck 而非空跑。
- 负控：临时把默认值改成 `tone = 42`，`pnpm --filter @vaultsyncd/ui typecheck` 退出码 1 并报 `src/StatusBadge.tsx(18,31): error TS2322: Type '42' is not assignable to type 'StatusTone'`；根脚本同样退出码 1（`ERR_PNPM_RECURSIVE_RUN_FIRST_FAIL`）。用备份还原后 `cmp` 逐字节一致，再次退出码 0。
- `find . -name pnpm-lock.yaml -not -path '*/node_modules/*'` 只有 `./pnpm-lock.yaml`；`find . -name package.json -not -path '*/node_modules/*'` 只有 `./package.json` 与 `./packages/ui/package.json`，与真实目录一致；无嵌套锁文件、无 `dist/`、无 `result*`。
- `git check-ignore -v node_modules packages/ui/node_modules` 均命中 `.gitignore:10:**/node_modules/`；`pnpm-lock.yaml` 未被忽略。
