## 3. 实测结论与限制

- **必须按 C 尺寸传 `ParamSize`**：`CF_OPERATION_PARAMETERS::ParamSize` 是 48（整个联合体结构），不是 `TransferData` 分支的 40；`Offset/Length` 也要取 `CF_CALLBACK_PARAMETERS::FetchData` 的请求范围。否则 `CfExecute` 回执 `0x8007017C`（`ERROR_CLOUD_FILE_INVALID_REQUEST`），读取最终超时 426。已在 `raw.rs` 用 `const` 断言与 `CF_OPERATION_PARAMETERS_SIZE` 固化。
- **目录占位符的 find-data 状态不可靠**：`FindFirstFileW` 直接查路径时目录属性不含 `FILE_ATTRIBUTE_REPARSE_POINT`，`CfGetPlaceholderStateFromFindData` 返回 `0x00000000`；`CfGetPlaceholderInfo`（非占位符返回 `ERROR_NOT_A_CLOUD_FILE`）是可靠来源，日志用 `placeholder_source` 标注。`attrib` 对占位符报 `Path not found`，不作为证据。
- `CF_POPULATION_POLICY_FULL` 下，提供方不在线时枚举占位目录会报 “The cloud file provider is not running.”（预期行为，原型不依赖枚举）。
- 产物**不逐字节可复现**（MSVC 链接阶段写入调试信息签名），验收用当次两端 SHA-256 比对，不维护金样哈希；S009 交接里记录的冒烟哈希只代表当次构建。
- 未实现（明确留给后续卡）：内容水合/取消/离线（S011）、释放与写保护（S012）、Explorer/GUI 展示、崩溃后注册残留的自动恢复（本卡只提供 `cleanup` 收尾）。
- 只在 `C:` 卷 NTFS、build 26300 上实测；ReFS、非系统卷、多提供方并发未验证。
