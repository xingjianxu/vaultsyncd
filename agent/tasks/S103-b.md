## 装置

`test-volume.sh create <run_id> 512M` 建独立 btrfs loop 卷并挂到 `<run>/mnt`；脚本创建子卷 `root` 与 `decoy`，把 `root` 真实挂载到 `<mnt>/rootmnt`（注册的 Root）；内部状态也放在该卷（准入要求 Root 与状态同一 btrfs）。卸载 `rootmnt` 后原路径露出主文件系统上的空目录，即 T19 现场。脚本 `trap EXIT` 卸载叠加挂载、detach loop、删除本 run 子卷/镜像，并核对无残留。

环境变量：`VAULTSYNCD_S103_MOUNT`、`_ROOT`、`_LOOP`、`_ROOT_SUBVOL`、`_DECOY_SUBVOL`、`_ALIAS_BASE`。

## 注入方式与判据

| 用例 | 真实动作 | 判据 |
| --- | --- | --- |
| `real_unmount_pauses_root_and_never_deletes` | 服务运行中 `sudo -n umount -l <rootmnt>`（服务持 Root 句柄，普通 umount EBUSY）；在露出的空目录写同名诱饵；期间上传并 put；随后重新挂载原子卷 | `unavailable` + `blocked` 且带原因；诱饵/客户端内容零事件、零版本；put `503 ROOT_UNAVAILABLE`；固定版本/revision 不变、零删除；重挂载后字节恢复为原内容，仍保守暂停、零删除 |
| `subvolume_replacement_and_bind_aliases_pause_root` | ① bind Root 到允许基目录下再注册；② Root 内 bind 外部目录；③ `umount -l` 后把 `decoy` 子卷挂到 Root 路径；④ 挂回原 Root 子卷 | ① 422 `UNSUPPORTED_STORAGE_BACKEND`、`details.reason=duplicate_root`，Root 数仍为 1；② `submount_detected`、外部内容零事件/零读取、原条目零删除；③ decoy 内容零事件、零删除、版本不变；④ 可见字节回原内容，仍暂停但零删除 |

## 限制

- 重新挂载/子卷替换改变 mount id，Root 按现有保守语义持续 `ROOT_UNAVAILABLE`，需要重新准入；本卡只证明期间零删除、零采纳、字节可恢复。
- 卸载使用管理员 `umount -l`（服务持有目录句柄时的真实手段），只作用于本 run 自建卷。
