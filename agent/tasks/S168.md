# S168 — GitHub 发布不再上传运行库对应源码归档

状态：done（实现、契约验证、交接与整合完成）。
依据：2026-11-09 用户明确要求发布 Release 时不上传 sources 包，并确认所指为 `vaultsyncd-runtime-sources.tar.gz`、该归档仅留在本地构建目录。前置 S156（本地发布入口）、S165（v0.1.2 发行）done；无产品规格冲突：design §25 未要求该附件上网，`docs/operations/linux.md` 的“分发二进制须同时提供对应源码”是许可约束，本卡改为“不在 GitHub 附件中提供，由发布者随二进制另行提供”。

结果：`packaging/github-release.py` 只把平台归档、平台来源收据、根 `release-manifest.json`、`build-SHA256SUMS` 和 `SHA256SUMS` 作为 Release 附件；Linux 对应源码归档仍必须在构建目录里、继续按组件收据核对 SHA-256（缺失或改字节即拒绝发布），但不进入上传集合。`--dry-run` 计划新增 `local_only` 字段披露该本地专属归档；自动生成的发布说明在含 `linux-x64` 时补一句“本页不含 Linux 运行库对应源码归档，随二进制分发时另行提供”。`release.py`、`nix/portable.nix`、容器入口仍照旧生成/校验该归档，本地保留行为不变。

关键入口：`packaging/github-release.py`（`LOCAL_ONLY`、`bundle`、`publish` 说明文字）；文档 `packaging/README.md`（附件清单、`local_only`、旧草稿含该附件时 `--resume` 会因“多余附件”拒绝，需人工删除该附件或重开草稿）、`docs/operations/linux.md`、`docs/architecture/interfaces.md` S156 条目；契约 `tests/contract/github_release.py`。

验证（均 exit0）：devShell 内 `python3 tests/contract/github_release.py` 基线 23/23、实现后 26/26；新增三例——`vaultsyncd-runtime-sources.tar.gz` 不在上传集合、收据哈希与本地归档不符时拒绝（“对应源码哈希不符”）、`--dry-run` 的 `local_only` 与 `assets` 一致；发布说明披露按平台正反两例。`python3 -m py_compile` 两文件通过。真实产物 dry-run（`/data/vaultsyncd-dev/S165-release-20261109/releases/v0.1.2-d976376669ce`，源 `d976376`）输出 7 个附件且 `local_only` 为该归档，全程未联网、未上传。未执行真实 GitHub 上传（本卡不发行）。

限制：不含该附件的 Release 不再自带对应源码，Linux 发行合规提供方式由发布者负责（本卡只记录口径，不改许可文本）；S165 之前的草稿若已上传该附件，`--resume` 会判为多余附件而拒绝，需人工删除后重试；未改动线上服务、已发布 Release、客户端更新渠道与首发门禁（S011/S106/S107/S108 blocked 保持）。
