## 1. 接口决定

- **新模块 `crates/planner/src/first_sync.rs`，入口 `plan_first_sync(local: Option<&LocalFact>, remote: Option<&ServerFact>, mode: BindingMode) -> Result<Plan, PlanError>`**。两侧 `Option` 必须是**同一规范路径**上的事实，`None` 表示该侧没有该路径；调用方按导入清单逐路径配对调用。
- **首次合并与旧设备重建是不同入口（本次不共用）**：本入口在类型上**不接受基线参数**，因此不可能把“另一端没有”当成删除（I07）。曾经同步过、只是游标过期的设备必须带旧基线走 `reconcile::reconcile`（design §9.2 末段）；无基线时 `reconcile` 只返回 `Defer(FirstSync)` 作为转交信号，由上层改调本入口。测试 `first_sync_is_a_separate_entry_from_baseline_reconcile` 钉住这条分工。
- **`BindingMode { Full, OnDemand }`**：design C34 的两个模式，只影响“仅远端存在”的条目——`Full` 的文件必须先 `DownloadVersion` 再呈现（I05），`OnDemand` 只建占位、没有下载依赖；目录两者都只需父目录就绪。客户端 Binding 配置落地时映射到该枚举，不保留第二套拼写。
- **计划动作复用 `reconcile::Action`（新增 4 个变体，S019 已有分支行为不变）**：`UploadNewEntry { generation }`（本地独有：服务器新建条目）、`CreateFromRemote { entry_id, revision, version, mode }`（远端独有：本地建占位或下载）、`BindRemoteEntry { entry_id, revision, version }`（同路径同类型同内容：只关联远端 `EntryId` 与基线，不传内容）、`PreserveBoth(PreserveReason)`（`ContentDiffers` / `KindDiffers`：双方都保留，服务器条目保留名称）。
- **前提扩两个**：`ServerPathVacant`（首次合并的创建 CAS，design §9.2 第 8 步：上传前服务器该路径仍为空）、`LocalPathVacant`（避免远端占位/下载覆盖扫描之后新建的本地内容，I02）。**错误扩一个**：`PathMismatch`（两侧路径不同 = 调用方没有按规范路径配对；此时绑错 `EntryId` 会写错基线，宁可报错）。
- **每个分支的前提/依赖**：本地独有 → 前提 `GenerationUnchanged`、`TargetPathUsable`、`ServerPathVacant`；依赖 `ParentDirectoryReady` +（文件）`SnapshotLocalContent`；保护 `UploadSnapshot`（目录为 `KeepLocalContent`，目录没有内容快照）。远端独有 → 前提 `BaseRevisionCurrent`（快照修订）、`TargetPathUsable`、`LocalPathVacant`；依赖 `ParentDirectoryReady` +（`Full` 的文件）`DownloadVersion`；保护 `NotNeeded`。同内容绑定 → 前提 `BaseRevisionCurrent`、`GenerationUnchanged`，无依赖，保护 `KeepLocalContent`。保留双方 → 同样两个前提，无依赖（副本身份归 S021），保护 `KeepLocalContent`。
- **判定只看类型与内容**：内容相同按长度 + SHA-256（`EntryKind` 相等），`mtime` 与名称相似度都不参与；目录之间按名称合并，`version: None`。
- **`Full` 模式下远端文件给不出 `VersionId` → `Defer(IncompleteFacts)`**：不把“必须下载完整内容”降级成占位；`OnDemand` 模式仍可占位。
- 未做（不预置占位）：服务器一致性元数据快照（`snapshot_id + epoch + high_water_seq`）与本地导入清单归扫描/会话层；快照期间事件接续与上传前 CAS 的执行归执行器；冲突副本名称、`OpId` 与长度预算归 S021。

## 4. 限制

- 每个规范路径一个计划：本模块不枚举同级条目、不检查父目录存在性/目录环/名称在目标文件系统上的可表示性（前提与依赖交给执行器核对），也不做冲突名称预算（S021）。
- 计划不携带 `OpId`/任务 id：重试幂等归 agent-core 执行器卡；同一输入重复计算只保证计划相同，不代表重试不会产生新业务操作。
- `BaseRevisionCurrent` 在首次合并里指“快照观察到的远端修订”（名称沿用 `reconcile`）；执行器必须真的按该修订做 CAS（design §9.2 第 8 步），否则本地独有上传可能覆盖快照之后新建的服务器条目。
- `PreserveBoth` 只声明“双方都保留 + 服务器保留名称”，本地副本的名称、副本身份与上传快照由 S021 给出，因此本卡不给依赖；执行器不得把它当成终态（进度/问题页展示归执行器）。
- `Full` 模式下远端文件缺 `VersionId` 只给 `Defer(IncompleteFacts)`，执行器不得自行降级成占位。
- 尚未接执行器、客户端存储与扫描层；`BindingMode` 目前只有本 crate 内的定义，Binding 配置卡落地时映射到它。
