## 1. 结果与接口决定

- 新增 `crates/platform-linux-server/src/files/`（仍无第三方依赖），在 S013 的 `mounts/` 之上实现“受限句柄读写 → 目标文件系统内暂存 → 刷盘 → 受控替换”。
- 模块：`raw`（`openat2`/`openat`/`renameat2`/`unlinkat`/`fsync`/`fchmod`/`FICLONE`；`struct open_how` 24 B 与常量有 const 断言，`__NR_openat2=437`）、`restricted`（`RestrictedDir` 根句柄 + 相对名称校验 + 两种解析机制）、`identity`（`statx` 身份/指纹、前提核对，纯逻辑）、`hash`（零依赖 SHA-256，NIST 向量）、`clone`（FICLONE/校验复制 + 失败分类）、`publish`（两步发布与结果渲染）。
- **解析**：优先 `openat2(RESOLVE_BENEATH|RESOLVE_NO_SYMLINKS|RESOLVE_NO_MAGICLINKS)`；逃逸 `EXDEV`→`escape_rejected`、符号链接 `ELOOP`→`symlink_rejected`；**只有 `ENOSYS` 才回退**逐段 `openat`+`O_NOFOLLOW`（`EPERM` 等不回退），输出 `resolve=` 标明实际机制。相对名称在系统调用前拒绝空/绝对/`.`/`..`/空段/NUL/超长段。
- **暂存**：暂存文件建在**目标目录**内（`O_CREAT|O_EXCL`），创建后核对 `staging_mount_id == target_mount_id`，因此跨文件系统时暂存天然在目标侧。
- **复制**：`classify_reflink_failure` 只让 `EXDEV`（→`fallback=exdev`）与 `EOPNOTSUPP`/`ENOTTY`/`EINVAL`（→`fallback=unsupported`）退回校验复制；`EIO`/`ENOSPC`/`EDQUOT`/权限错误直接失败（`reflink_failed`），不重试、不伪装。校验复制=写入后 `fsync`+读回比对长度与 SHA-256+源 `statx` 前后指纹（变化即 `source_changed`）。
- **替换**：拆成 `stage_for_publish`（前提核对→暂存）与 `commit_staged`（**替换前再核对**→`fchmod`→`renameat2`→`fsync` 目录→发布后核对身份/大小/权限），`publish` 为便捷组合；新建用 `RENAME_NOREPLACE`（内核竞争 `EEXIST`→`target_appeared`），替换用 0 旗标原子替换。前提不成立即**暂停**：目标不改、候选保留（`candidate`/`candidate_dir`/`candidate_sha256`）。对象模式 `0444`，工作文件 `0644`。
- `mounts::raw` 从私有改为 crate 内可见（`files/` 复用 `statx_of_fd`），并补齐 `size`/`mtime`/`ctime`/`nlink`/`mode` 字段与对应 `STATX_*` 请求位；`tests/platform/linux/common.sh` 的断言辅助统一读取 `CMD_OUT`/`CMD_STATUS`（`run_admission` 保留 `ADMISSION_*` 别名，S013 脚本无需改动）。
- 原型命令 `examples/file-publish`（`identity`/`hash`/`capture`/`publish`/`rename`，退出码 0 成功、3 拒绝、1 错误、2 用法）。`publish --race-hook` 仅在两步之间执行一条命令，用于验收外部竞争，不是产品写入路径。

- `VAULTSYNCD_RUN_ID=s014-final bash tests/platform/linux/run-file-publish.sh` → 0，`用例：100 项，失败 0 项`（日志 `artifacts/s014/final.log`，不入 Git）。关键证据：`openat2` 与 `--resolve walk` 同一 inode 257；4 MiB 样本 `hash` 与 `sha256sum` 一致；同卷跨子卷 `capture` 得 `method=ficlone`/`fallback=none`/`mode=0444`/共享 extent 1 行；外部改写工作文件后对象 SHA-256 与字节不变（`cmp` 一致）；对象→工作文件新建与按身份替换（inode 259→260）；外部竞争两路径：暂存前变化→`target_changed` 无候选，暂存后注入 `mv`→`target_changed` + 候选保留（哈希等于源对象）+ 目标仍为注入的 54321 字节；`--expect absent` 撞已存在→`target_appeared`；跨文件系统（挂载 68 vs 363）`verified_copy`/`fallback=exdev`/`reflink_error=Invalid cross-device link (os error 18)`/无共享 extent/暂存仍在目标挂载；跨设备 `rename`→`cross_device_rename` 且源文件仍在；符号链接（末段/中间段）、`..`、绝对路径全部 exit 3。
- 回归：`run-storage-admission.sh` → 0（`用例：60 项，失败 0 项`），`run-reflink.sh` → 0（`7 项 0 失败`），确认 `common.sh` 改动无回归。

## 4. 限制

掉电/崩溃恢复与 `fs_intent` 重放未实测（fsync 只验证返回成功）；替换与外部写入之间的窗口仍在（C33，只承诺“观察到不一致就暂停并报告”，未做高速并发压力测试）；暂存名在目标目录内对观察者短暂可见；跨文件系统复制只测 4 MiB，无满盘/中断样本；`0444` 只挡普通写入者（同用户可 chmod、root 可改写）；本 crate 仍不在 `default-members`，`cargo xtask check`/CI 不构建它。
