# S136-c — 跨 Root 同摘要对象登记与物理布局修复

状态：done（父卡 S136 内）。隔离/基线同 [S136](S136.md)；实现细节见 [S136-c-implementation](S136-c-implementation.md)，规范入口 `docs/architecture/interfaces.md` S136-c、design ADR-020、§11.5。

根因（真实证据）：旧实现 `objects` 行按 `(root_id, hash)` 归属、`storage_path` 全库唯一且不可更新，但已发布对象统一写在 `state_dir/objects/objects/<aa>/<hash>`。第二个 Root 上传相同摘要时与唯一约束冲突，finalize 503 `NEEDS_RECOVERY`（`/data/vs-s136-20261108T203849-3120679/server.log` 第 48 行）；不同 Root 共享物理文件也无法按 Root 独立 GC。用户在获知需统一十余模块并兼容旧数据后，明确选择本轮一并完整修复（ADR-020）。

修复：新对象写 `objects/roots/<RootId>/objects/<aa>/<hash>`，一 Root 一对象行，保留 `UNIQUE(storage_path)`、不可变触发器与外键。旧行不迁移不改写；`object_layout::for_root` 仅按该 Root 已登记摘要开放旧路径，不读磁盘猜测、不跨 Root fallback，登记不可读即失败关闭。finalize/重放、下载与版本租约、create/put/conflict/delete 现场复核、外部采集、启动 replay、GC 路径校验、备份 prepare/export、server-admin 离线 restore 全部按 Root 取布局；热路径按摘要解析（`for_digests`/`for_digest`，一次主键查询），只有外部扫描、删除整树核对和回收站/历史恢复等多摘要路径才一次读取该 Root 全部旧登记（实测 10 万行约 90—100 ms，避免落在每次文件读写上）；备份归档成员仍为 `objects/<RootId>/<hash>`，清单允许 legacy 或该 Root 新路径并拒绝重复物理登记。`0015_root_scoped_objects.sql` 仅提升语义版本到 15（无表结构变化），使 target≤14 旧二进制拒写；14→15 走既有迁移前一致性备份，失败不返回可写句柄，回退用整套备份。

验证（均 exit0）：`cargo test --workspace`；`cargo test -p vaultsyncd-server-store -p vaultsyncd-server-core -p vaultsyncd-server -p vaultsyncd-admin -p vaultsyncd-server-tests`；`cargo fmt --check`；`cargo clippy --workspace --all-targets -- -D warnings`。新增关键用例：HTTP 两 Root 同摘要独立 finalize/reuse/replay 与跨 Root 403、旧登记路径新上传与重放、14→15 备份/不可变行保持/旧二进制拒写/失败迁移无写句柄、备份清单 legacy+scoped 与重复/穿越拒绝、GC 两 Root 同摘要独立回收且只保留存活一侧行、真实浏览器 `cross-Root-copy`。按摘要解析优化后又完整重跑 `cargo clippy --workspace --all-targets -- -D warnings`、`cargo test --workspace` 与 S136/files/recovery/backup 四套真实浏览器验收，均通过。修正了审查发现的两处问题：备份测试原用 UPDATE 触发不可变触发器（改为断言触发器拒绝并 INSERT 模拟损坏库）；executor 测试模块位置触发 clippy。

限制：旧对象不做物理搬迁，磁盘仍保留旧目录（由所属 Root 的对象行管理）；旧二进制回退只能整套备份恢复，不自动降级；本轮未做生产部署（需另立部署卡）。证据：`artifacts/S136/{cargo-test-*,clippy*,browser-final-all}.log`（Git 外）。
