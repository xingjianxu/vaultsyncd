## 接口与路径

- `platform-linux-server::ipc` 在 `<state.dir>/admin/socket` 提供有界 Unix socket：目录 0700、socket 0600，O_NOFOLLOW 目录 fd 锚定操作、双向 SO_PEERCRED，同服务有效 UID；1 MiB 帧、16 并发、10 秒截止。默认不覆盖既有路径；持状态锁启动时只回收合法遗留 socket（S075-c），优雅退出仅清理自身 inode。
- `apps/server/src/admin.rs` 装配在线用例；`roots.rs` 抽取 HTTP/本机共用 Root 清单及注册准入事务；store 增加有界 Root 页。真实历史/回收站读取 committed 状态，`problems` 复用挂载身份/可读性探测及持久冲突，绝不以 NotReady/空列表代替实现。
- `vaultsyncd-admin {status|roots|problems|history|trash} --socket <绝对路径> --json`；`roots register <路径>` 只走在线进程。schema 唯一文档源 `api/admin-socket.schema.json`，动态 JSON 不增加并行手写 DTO；接口细节见 `docs/architecture/interfaces.md` 的 S075 节。离线 init 原样保留状态锁；不改 Windows IPC。

## 限制与恢复条件

- 仅服务 UID、唯一 active owner；零个/多个明确 409。新增管理组/多角色授权不在本卡；管理员使用 `sudo -u <服务账号>`。
- 清单固定 100 条、实时偏移分页，不承诺跨页一致性；需要一致性清单用现有 snapshots API。problems 按候选分页，健康 Root 被过滤后可能空页但仍有 next_page；没有伪造尚未持久化的逐文件问题目录。
- roots 清单健康来自数据库，problems 才做实时挂载复核；既有 `pending_import=true` 行为不改。新管理 socket 不是 HTTP 代理入口；远端只走 SSH 或已认证 HTTPS。
- 崩溃遗留 socket 由 S075-c 自动恢复：`bootstrap::prepare` 先独占状态锁，再回收锚定 admin 目录内、`lstat` 为 socket 且属主为服务有效 UID 的遗留 inode；非 socket/符号链接/他人属主明确失败，不删除 DB 或恢复证据。第二个活服务端在锁处被拒绝，不会覆盖实时 socket。该修复使 `kill_boundaries` 4 项恢复通过。注册超时/断线结果未知，先查 roots 核对，不能当作未提交自动重放。
- 无本卡验收阻塞；未执行无关前端/Windows 验收，不触碰其 VM、端口/进程/卷。`agent/progress.md` 按父协调要求未编辑。
