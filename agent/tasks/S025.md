## 1. 接口决定

- **两份契约分开**：`api/local-ipc.schema.json`（JSON Schema `2020-12`）是本机 IPC 唯一编辑源，与 `api/openapi.yaml` 互不引用。服务器管理 API 不因此获得控制客户端本地路径的入口；本机 IPC 不经网络传输。`api/generation.toml` 升到 `format_version = 2`，新增 `local_ipc_source`/`local_ipc_schema_draft` 与 `[outputs]` 的两个本机路径，`[types.*]` 两份契约共用。
- **契约内容**：`Request{request_id, ipc_version, command}`、`Command{name}`、`CommandName` 闭集（当前只有 `get_status`）、`Response{request_id, kind, result?, error?}`、`ResponseKind{ok,error}`、`GetStatusResult{agent_version, ipc_protocol}`、`ErrorBody{code,message,retryable}`、`LocalIpcErrorCode` 闭集（当前只有 `unsupported_version`）、`IpcVersion{major,minor}`。未知命令/未知种类/未知错误码在解码阶段被拒绝，没有 catch-all。
- **长度限制进契约**：文档头 `x-vaultsyncd` 声明 `protocol{major:1,minor:0}` 与 `frame{header_bytes:4,max_frame_bytes:1048576}`，生成器校验后生成两侧常量（Rust `PROTOCOL_*`/`FRAME_HEADER_BYTES`/`MAX_FRAME_BYTES`，TS 同名），帧实现与测试引用同一份数字，不另写副本。生成器拒绝 `header_bytes != 4` 与 `max_frame_bytes` 不在 64 B—64 MiB 之间。
- **帧**（`crates/local-ipc/src/framing.rs`）：4 字节大端长度头 + JSON 负载。`FrameDecoder::push` 接受任意切分（含 1 字节一块），只有凑满声明长度才产出负载，截断数据永不产出短帧；声明为 0、超过上限、积压超过 `MAX_QUEUED_FRAMES = 4` 帧即报 `FrameError`。等待中的部分帧最多 `4 + MAX_FRAME_BYTES`，报错后连接应由传输层关闭（S071）。
- **GetStatus 与版本**：`version::is_compatible` 要求 major 相同且 minor 不高于 agent 支持的版本（调用方可能假设未实现的命令存在）；`Service::handle` 对不兼容版本返回 `unsupported_version`（`retryable = false`）并回显 `request_id`，兼容时返回 agent 版本与 `ipc_protocol`。`Response::ok/error` 是唯一构造路径，`Response::validate()` 供解码侧复核 `kind` 与负载一致。
- **可选字段一律“缺省即不存在”**：生成器给 Rust 的 `Option<T>` 加 `#[serde(skip_serializing_if = "Option::is_none")]`（远端生成的 `ErrorBody.details`/`root_id` 也随重新生成获得该属性，行为与其文档“与 Root 无关时省略”一致）。这让“解码后再编码等于样本”在两侧都成立，也是本卡“Rust 与 TS 样本一致”的判定方式。
- **生成器重构**：`tools/xtask/src/generate/` 拆成 `mod.rs`（配置、远端模型、共享 schema 校验）、`local_ipc.rs`（JSON Schema 解析与 `x-vaultsyncd` 校验）、`emit.rs`（共用 schema 渲染 + 两份契约的表头/常量）。`$ref` 前缀参数化（`#/components/schemas/` 与 `#/$defs/`），其余校验规则不变；远端生成结果除上述 serde 属性外逐字节不变。

## 4. 限制

- 契约只覆盖 `Request`/`Response`/错误信封与 `get_status`。design §15.5 其余十个命令与其结果、状态推送帧（含快照版本号）在 S072 扩展；届时 `GetStatusResult` 需要加入 Binding/问题/快照字段，并决定长计数仍走十进制文本（本卡未引入 `decimal_u64`，因为当前契约没有长计数）。
- `request_id` 只按不透明文本处理：没有长度/字符集校验（生成器不支持 `minLength`/`maxLength`），也不据此授权。传输层负责连接身份。
- 帧层没有压缩、批量或超时：这些属于 S071 的传输实现；`FrameDecoder` 报错后连接不可继续使用是刻意的保守策略。
- 已知宽容：Rust 的 `Option<T>` 对显式 `null` 与缺省都解出 `None`，而 TS 解码器只接受缺省（`null` 视为畸形）。正常链路两侧都由生成代码写出且不写 `null`，样本也没有；若后续要求严格对等，需让生成器对可选字段拒绝 `null`。
- 生成器的 JSON Schema 子集与 OpenAPI 子集相同（对象/闭集字符串枚举/布尔/整数/字符串/数组/字符串映射），不支持 `oneOf`/`anyOf`/`nullable`/`pattern`/`minLength`；需要时先扩生成器。
- `packages/local-ipc-types` 的运行时断言不在 `cargo xtask check` 内（与 S024 相同），IPC 相关卡需手动跑 `pnpm --filter @vaultsyncd/local-ipc-types test`；是否纳入 CI 留给 S101。
- 未与 agent-core、apps/agent 或桌面应用接线：`Service` 目前只持有 agent 版本字符串，真实状态来源在 S064/S070 提供。
