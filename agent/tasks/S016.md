## 1. 接口决定

- **六个正交维度**（`crates/domain/src/state.rs`，拼写与 design §8.1 一致）：`Residency`（`MetadataOnly`/`Partial`/`Materialized`）、`Dirty`（`Clean`/`Dirty`/`Snapshotting`/`AwaitingCommit`）、`RemoteApply`（`Current`/`Pending`/`BlockedByLocal`/`Conflicted`）、`Transfer`（`Idle`/`Queued`/`Running`/`RetryWait(ErrorCode)`/`Failed(ErrorCode)`）、`Usage`（`Idle`/`ReadHandles`/`WriteHandles`/`Unknown`）、`Availability`（`Online`/`Offline`/`MountFailed`/`RootUnavailable`）。`EntryState` 只有这六个字段，`Default` 是“仅云端、clean、current、idle、idle、online”，因此 `dirty + offline + materialized` 这类组合可直接构造。
- **错误码跟随任务维度**：design §8.1 只列六个维度，所以失败原因不作为第七个字段，而是挂在 `Transfer::RetryWait`/`Failed` 上（`error_code()` 取值）。显式接口 `Transfer::Failed` 表示已停止自动推进，`RetryWait` 只应携带可重试类别；这条不变式写进类型文档，投影对违反组合保守处理。
- **主状态投影** `EntryState::project() -> EntryStatus`：按 design §8.2 的优先级给出唯一主状态——`Unavailable`（挂载失败/Root 不可用）> `Failed`（`Failed` 任务，或 `RetryWait` 携带严重类别）> `Conflict` > `LocalChanges` > `Syncing`（`remote_apply != Current` 或任务非 `Idle`）> `Downloaded`（`Materialized`）> `CloudOnly`（`MetadataOnly`/`Partial`）。纯函数、无 I/O；`Partial` 不投影成已下载；`Usage` 只供破坏性操作准入，不改变主状态。
- **“已同步”判断** `EntryState::is_synced()`：`dirty = Clean` 且 `remote_apply = Current` 且任务不是 `RetryWait`/`Failed`。`Pending`、`BlockedByLocal`、`Conflicted` 和任一待上传修改都为假，满足“pending 不能投影成已同步”；`Queued`/`Running` 的下载/哈希任务不改变“基线一致”，`Residency`/`Availability` 不参与判断（离线不改基线，界面另读维度显示“仅云端/当前离线”）。该判断不能当下载状态使用。
- **错误分类**（`crates/domain/src/error.rs`）：`ErrorClass` 为 `Retryable` / `NeedsUserAction` / `Corrupt`，`is_severe()` 仅对后两者为真（design §8.2 严重失败、§18.2 问题页）。`ErrorCode` 收齐 design §15.4 的 23 个码（18 服务端 + `LOCAL_CHANGED`/`FILE_BUSY`/`MODE_REQUIRES_LOCAL_COPY`/`PLACEHOLDER_OFFLINE` + `MOUNT_FAILED`），以宏一次声明 `as_str()`（wire 拼写唯一来源）、`from_code()`、`class()`、`ALL`、`Display`。
- **归类依据**（design §15.4 每行的“客户端处理”）：重新规划/重建/退避可推进的（`BASE_MISMATCH`、`SUBTREE_CHANGED`、`RECONCILE_REQUIRED`、`CURSOR_EXPIRED`、`EPOCH_CHANGED`、`RATE_LIMITED`、`LOCAL_CHANGED`、`FILE_BUSY`、`PLACEHOLDER_OFFLINE`）为 `Retryable`；必须停止并交给用户/管理员的（权限、挂载、额度、配置不支持、历史过期、`OP_ID_REUSED` 协议违规）为 `NeedsUserAction`；只有 `HASH_MISMATCH` 为 `Corrupt`（未过校验的内容不得发布）。`AUTH_EXPIRED` 归 `NeedsUserAction`：一次性受控刷新由调用方在分类前完成，分类表达终态处理。
- **wire `retryable` 与分类不冲突**：`ROOT_UNAVAILABLE` 在 design 示例里是 `retryable: true`，本分类仍是 `NeedsUserAction`——低频复查不能替代用户恢复挂载。`from_code()` 对未知代码返回 `None`，不默认归入可重试。

## 4. 限制

- 投影只决定“显示什么”，不代替执行器重新校验；领域层不生成状态值、不写库、不调度重试（重试次数、退避与 `Retry-After` 归后续调度/执行器卡）。
- `EntryState` 字段公开、不变式只写在文档并由投影保守兜底，没有运行时校验器；若后续状态写入方需要拒绝非法组合，再补显式校验（本卡不预置）。
- 目录级“已同步”按子任务/失败/冲突汇总（design §8.1 末句）未实现，留给 planner/客户端存储卡；本卡只做单条目投影。
- `ErrorCode` 的 `as_str()` 目前是错误码 wire 拼写的唯一来源；S024/S025 的 schema 生成必须复用它（或生成后核对），不得另写字符串副本。
- `Failed` 一律按严重失败显示；若调度器想把“可重试但暂停”的状态也放进 `Failed`，需要先扩展该维度的语义，不能靠 `ErrorClass` 自行降级。
- 未与持久化、选区或 UI 接线；`Usage` 尚无破坏性操作消费者。
