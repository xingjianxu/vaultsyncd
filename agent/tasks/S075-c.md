# S075-c — 崩溃遗留管理 socket 的自动恢复（S075 回归修复）

## 安全依据与实现

- 启动顺序已满足“先锁后 socket”：`bootstrap::prepare` 先 `StateLock::try_acquire_exclusive(<state>/server.lock)`，再打开数据库、评估恢复、绑定 HTTP，最后调用管理 socket；第二个活服务端或离线 init 在锁处即被拒绝。因此持锁时存在的 `admin/socket` 只可能是上一个持锁进程被强杀后的遗留 inode，可程序化判定。
- `platform-linux-server::ipc` 新增 `AdminSocket::bind_after_state_lock`；原 `bind` 保持“拒绝任何既有路径”。回收只在已用 `O_DIRECTORY|O_NOFOLLOW` 打开并校验过的 admin 目录 fd 内，对 `/proc/self/fd/<dirfd>/socket` 做 `lstat`：仅当类型为 socket 且属主为服务有效 UID 才 unlink；普通文件返回 `AlreadyExists`、符号链接/他人属主明确失败，均不删除。删除后仍由 `UnixListener::bind` 新建，Drop 只清自身 inode。
- `apps/server/src/bootstrap.rs` 改调用 `bind_after_state_lock`，并在注释中固定“锁→socket”的安全前提。未调整启动顺序，未改帧协议、CLI、schema 或数据库。
