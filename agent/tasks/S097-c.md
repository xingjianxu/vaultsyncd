# S097-c — 持久 Root 身份与进程挂载围栏

状态：in_progress；父明确要求修复实际部署一致性缺陷后S097才done。证据：S096专用systemd实例经服务重启，Root58e698...的DB健康healthy而管理页/问题清单unavailable/mount_changed；HTTPS上传/SSE成功，截图真实暴露诊断误差，不能只看全局health。

根因：root_file_identity历史RootSnapshot含进程/namespace临时mount_id，健康诊断直接把历史ID与新进程比较；观察器/执行器各自打开新句柄却不统一对持久身份作启动核对。不能忽略平台在线mount_id、删除重注册或手改在线DB。

实现方案：服务启动时只读核对持久FS UUID/subvol/canonical目录/inode/btime及完整CoW/嵌套准入，建立本进程不可自动替换的RootSnapshot围栏；历史blob不改格式/不回写。新Root仍严格使用本进程注册快照。健康/观察/执行/启动重放共用围栏，活进程内bind/卸载/权限漂移仍blocked；不同持久身份或不完整证据fail closed。出生时间/FSID必须可证明；设备号和mount_id只作本进程围栏，不跨进程持久比较。

验收：精确逻辑与负例、真实systemd重启同Root/版本不误漂移、真实同目录bind覆盖仍blocked且不推导删除、恢复原挂载后采集回到健康；新输入必须实际Nix构建并更新永久固定源。Windows原生/Edge已通过并清理归还S100，本子卡仅宿主，不重新占VM。记录/代码仍在S097树。

阶段检查点：共享RootFences实现并接入全部消费者，历史blob不回写；Linux平台73、server56单测通过，两包all-target Clippy -D warnings通过。离线fence-boundary示例只允许/data/vs-s097-fences-*，先取StateLock后用真实端口写入Prepared/Published，不增加生产故障开关；示例构建通过。真实systemd、bind和持久边界恢复、Nix包更新尚待执行，不能标done。旧FileKey没有birth，跨卷重挂dev变化时Prepared必须保守保留；Published用内容证明只收尾。普通同dev服务重启Prepared仍应redo，分别测量，不混淆namespace与卷重挂。
