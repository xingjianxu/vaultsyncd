## 结果

`tools/release.sh` 未改动：它是发布链入口，产物必须按 `v<版本>-<HEAD前12位>` 命名并带 `receipt.json`/`SHA256SUMS`/`release-manifest.json` 供 `tools/publish-release.sh` 与 `cargo xtask release assemble/verify` 消费，去掉版本号会破坏来源身份（`packaging/release.py` 的 `check_identity`、GitHub 发布预检均按版本+提交核对）。因此按备选新建 `tools/build.sh`：

- 可从任意目录调用；不在 `.#windows` 内时自动 `exec nix develop .#windows --command bash tools/build.sh`，不接受参数（多余参数退出 2）。
- 每次先 `rm -rf dist/` 再构建：`pnpm install --frozen-lockfile --offline` → 清除并重建 `apps/desktop/dist` → `cargo xwin build --locked --release --target x86_64-pc-windows-msvc -p vaultsyncd-agent -p vaultsyncd-cli -p vaultsyncd-desktop --bins`，`RUSTFLAGS=-C target-feature=+crt-static -C link-arg=/ignore:4099`（静态 CRT，客体无 `VCRUNTIME140.dll`）。尊重调用方 `CARGO_TARGET_DIR`，默认仓库 `target/` 以复用缓存。
- `dist/` 最终 11 个文件：五份 EXE、`installed-files.json`、`zip-files.json`、`UNSIGNED-TEST.txt`、`Start vaultsyncd.cmd`、`Stop vaultsyncd.cmd`、`README-ZIP.txt`、`build-info.txt`。两份清单复用发布链同一段 `packaging/windows/zip/build.py`（写 `zip-files.json`、打整包后逐文件复核），`source` 两份相同、`signature_status=unsigned-test`，只多记 `dirty` 描述开发构建。
- 不写收据、`SHA256SUMS`、`release-manifest.json`，不要求干净提交；`build-info.txt` 记录提交/树/版本/脏树、目标、RUSTFLAGS、构建时间与实测 rustc/cargo/node/pnpm。发布与 GitHub Release 仍只消费 `tools/release.sh` 的收据目录，本入口不是发布候选。

接口与语义见 `docs/architecture/interfaces.md` S184；操作入口见 `packaging/README.md`「开发构建（无版本号，直接写 dist/）」与 `docs/operations/windows-lab.md` §12.2。
