## 1. 接口决定

- **新建 `crates/transfer`（design §5.4 的规范落点）**：只放 `chunk.rs`（`ChunkGeometry`：块数 =
  `ceil(total/chunk)`、空内容 0 块、越界索引 `None`、`checked` 边界）与 `hash.rs`（`ContentHasher`
  增量 SHA-256、`digest_of`、`verify`）。摘要以**原始 32 字节**交付，不新造第三个摘要包装类型
  （`objects::ContentDigest` 与 `ObjectHash` 各自保留）。`server-store` 的
  `uploads::ChunkGeometry` 改为薄封装并调用 transfer，因此块几何**唯一权威是 `crates/transfer`**；
  `UploadRecord::geometry()` 随之返回 `Result`。
- **契约先落地（父会话决定）**：`api/openapi.yaml` 新增 `beginUpload`/`getUpload`/`putUploadPart`
  与 7 个 schema（`UploadRequest`/`UploadSession`/`UploadState`/`UploadStatus`/`ReceivedPart`/
  `MissingRange`/`UploadPartAck`）。生成器扩展：端点 `parameters` 只接受 `in: path` 必填参数
  （`type: string` 或 `format: decimal_u64`），必须与路径 `{name}` 占位符一一对应；请求体接受
  `application/octet-stream`（无 schema）。TS 客户端生成位置参数 + 模板字面量 URL +
  `encodeURIComponent`，`content-type` 由媒体类型决定。
- **两个新错误码**：`INVALID_REQUEST`（形状/越界索引/长度不符/超载荷 → 400）与 `PART_CONFLICT`
  （同索引不同字节 → 409）。design §15.4 的闭集没有这两类，属本次 wire 扩展，需在 design 表补行
  （父会话决定措辞）；客户端处理建议“不重试原样请求，按协议错误上报/重新查询会话”。
- **块哈希用请求头 `x-part-sha256`**（design §15.2「二进制块、块哈希」）：生成器暂不支持 `in: header`
  参数，因此它只写在端点描述里，TS 客户端经 `init.headers` 传入；契约层未声明该头，属已知缺口。
- **接收顺序固定**（`api::uploads::receive_part`）：读会话 → 状态必须是 `open` → 块几何给出期望长度
  → 摘要核对 → 已收块比较 → **落盘并 fsync** → 登记块行。越界/长度/摘要失败都在写盘之前返回；
  幂等重传不重写磁盘；登记失败只留下孤儿暂存文件，绝不会“已登记但无字节”。
- **跨会话访问**：上传会话与签发它的登录会话绑定，别的登录会话（即使同一 owner）读进度/传块都得到
  404，与“不存在”同一个回答，不泄露存在性。
- **并发与大小有界**：块载荷最多读到 `max_chunk_size + 1`（16 MiB + 1）就拒绝；总大小上限 64 GiB；
  会话默认 24 小时到期。**未做**每 Root 并发上传数上限（需要策略与产品决定）。
