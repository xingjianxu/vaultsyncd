# S194 — 修复 tools/build.sh 交叉编译失败（CLI 漏写 remove_connection）

状态：done（验收与交接完成）。用户报告 `tools/build.sh` 报错。复现：主工作区 `master`（`a4f58f0`，干净树）实跑，前端与 `cargo xwin` 交叉编译进行到 `vaultsyncd-cli` 时中断，退出码 101。

## 根因

```
error[E0004]: non-exhaustive patterns: `CommandName::RemoveConnection` not covered
   --> apps/cli/src/main.rs:633:11
```

S193（`c587d78`）在 `api/local-ipc.schema.json` 的 `CommandName` 闭集里新增 `remove_connection`（IPC 2.11）并重新生成 `crates/local-ipc/src/generated/mod.rs`，同步改了 agent、desktop 与 `crates/local-ipc/src/commands.rs`，但 `apps/cli/src/main.rs` 的 `command_label()` 穷尽匹配未更新。S193 的验证清单里没有 CLI 编译项（只列了宿主 client-store/local-ipc/typecheck/desktop 构建与原生交互验收），因此该断裂在合并后未被发现，直接表现为 `build.sh` 失败——该脚本用 `-p vaultsyncd-agent -p vaultsyncd-cli -p vaultsyncd-desktop` 交叉编译，CLI 是产品四件套之一。

这意味着 `a4f58f0` 的主干源码本身无法通过 `tools/build.sh`，与 dist 是否干净、devShell 是否可用无关。

## 结果

`apps/cli/src/main.rs`（唯一改动文件）：`command_label()` 补 `CommandName::RemoveConnection => "remove-connection"`，并注明 CLI 目前没有该子命令（移除服务器由桌面端发起）、保留映射是为了让闭集新增命令时在编译期暴露漏写。

不新增 CLI `remove-connection` 子命令：那属于产品面扩张（需要 USAGE、参数校验、`validate_result` 对 `session_revoked` 的判定与宿主测试），不在本次修复范围；如需要 CLI 与桌面端对齐，另开卡。

`validate_result()` 有 `_ =>` 兜底、`render_success()` 只按字段分支，两者无需改动；schema、生成代码、agent、desktop、`tools/build.sh` 均未改，宿主 `cargo xtask generate --check` 不涉及（未动 schema）。

## 验证（devShell 内实际执行）

- 复现：主工作区 `master` 实跑 `./tools/build.sh` → `error[E0004]`，`EXIT=101`（日志留在 `/data/vaultsyncd-dev/diag-build-20261111/build.log`）。
- 修复后宿主：`cargo check -p vaultsyncd-cli --all-targets` 通过；`cargo fmt -p vaultsyncd-cli --check` 无输出；`cargo test -p vaultsyncd-cli -p vaultsyncd-local-ipc` 全绿（6/20/9/1 项）。
- 修复后全流程：任务树内 `CARGO_TARGET_DIR=/wrd/prj/vaultsyncd/target ./tools/build.sh` 退出 0——pnpm 离线准备、desktop 前端重建、`cargo xwin build` release（37 s，复用主工作区缓存）、清单与整包复核、产物搬入 `dist/`（11 个文件，约 38 MB，四个 EXE 齐套）。
- 未做 Windows 原生运行验收：本卡只修编译断裂，不改运行期行为；`dist/` 仍是 `unsigned-test` 开发构建，不能当发布候选。

## 限制

- CLI 仍不能移除已保存的服务器，桌面端 UI/IPC 能力不变；两者差异由本卡注释明确记录。
- 复发风险留在流程上：新增 `CommandName` 变体时若只验证部分 crate，仍可能漏掉 CLI。建议后续在卡的验证项里固定包含 `cargo check --workspace --all-targets` 或直接跑 `tools/build.sh`。
