## 1. 接口决定

- **新建 `crates/http-client`（包 `vaultsyncd-http-client`）并进 `members` + `default-members`**：它是 design §5.4 指定的客户端唯一远端 HTTP 适配层，只依赖 wire 契约、`reqwest`(rustls)、`tokio` 与 `serde_json`，没有平台 API 与本地状态，因此两端共用、便携检查可跑（含真实 TLS 握手用例）。
- **端口在认证之上**：`Transport` 只做“发出字节、带回状态/头/体”，`ApiClient` 在其上装配 URL/头/体并实现 401 刷新、超时、取消与错误分类。这样测试替身替换的是纯传输，产品路径不会因为“测试开关”而分叉；`testing` 模块只在 `cfg(test)`/`testing` feature 下编译。
- **刷新合并用“代际 + 单飞锁”**：`AuthSession` 每次凭据变化把 `generation` 加一；401 的请求带着自己看到的代际去抢刷新锁，拿到锁后先比代际——别人已经刷新就直接复用（不再发请求）。因此并发 401 只产生 **1 次** 刷新，而且不依赖时间窗口。**一次请求最多刷新一次**：重试后仍 401 → `ReauthRequired{RetriedUnauthorized}`。
- **刷新失败分两类，都不丢本地状态**：刷新接口 401 → `ReauthRequired{RefreshRejected}` 且置 `needs_reauth`，凭据（含旧刷新凭据）原样保留；连接/超时/证书失败 → 原样返回该错误（`is_retryable`），代际、凭据、`needs_reauth` 都不变。队列不在本 crate（S054+），这里保证不产生“清空凭据/丢弃请求”的副作用。
- **TLS 只有加法**：`TlsTrust::{SystemRoots, SystemRootsWithAdditionalRoots}`，开发 CA 必须显式以 PEM（或文件）追加；仓库里没有任何关闭校验的配置项、环境变量或构造器。证书问题在错误链里递归下钻（rustls 错误被 `tokio-rustls` 逐层包进 `io::Error`，`io::Error::source()` 会断链，必须看 `get_ref()`），单独分类为 `TransportErrorKind::Certificate(UnknownIssuer|Expired|NotValidYet|NameMismatch|Revoked|Other)`，不可重试、不触发刷新。
- **重定向不跟随**：跨主机 3xx 会把 `Authorization` 带出去，因此 `redirect::Policy::none()`，3xx 按非 2xx 显式失败。
- **超时与取消**：每次请求套 `tokio::time::timeout`（覆盖发送与读响应体），默认 30 s、连接 10 s，可按请求覆盖；取消用 `Cancellation`（`watch` 通道），取消返回 `Cancelled`，不是失败。等待共享刷新时不会因为某个等待者取消就把别人的刷新丢掉。
- **错误分类服务于调度而不是替代它**：`Api` 的可重试性取服务端 `body.retryable`，`retry_after` 只解析秒数形式（HTTP-date 交给调度器按指数退避）；非 2xx 且不是错误信封（代理/网关）→ `UnexpectedResponse`（5xx 可重试）；2xx 但不合契约 → `Protocol`（不可重试）。403 与证书错误都不会被自动重试。
- **请求装配约束**：路径必须 `/` 开头且不含方案/查询串/片段/空白（查询串编码留给需要它的端点卡）；`Authorization`/`Content-Type`/`Content-Length` 由客户端生成，手写被拒；头名限 `[A-Za-z0-9-]`、值不允许控制字符；`base_url` 的路径前缀（如 `/vault/`）对每个请求保留。
- **凭据持久化是端口**：`CredentialSink::{credentials_stored,credentials_erased}` 由 agent 注入（OS 凭据库/受限权限文件，ADR 0001）；本 crate 不写文件。`Credentials` 的 `Debug` 隐去两个令牌（日志不泄露秘密，design §17.3）。

## 4. 限制

- **没有对真实服务端实例联调**：401→刷新→重试链路用传输替身验证（含真实 TLS 握手），没有对着 `apps/server` 的 HTTPS 监听做端到端跑；S051/S052 的闭环卡与部署卡（S097 HTTPS 部署）才有真实实例。
- **`Retry-After` 只解析秒数形式**：HTTP-date 形式返回 `None`，由 agent 执行器按指数退避处理；退避与抖动本身属 `crates/agent-core`（后续卡）。
- **没有检查 `access_expires_at` 做提前刷新**：到期只由服务端判定（避免客户端时钟偏差造成误刷新）；若后续卡需要“提前刷新”策略，应作为调度策略显式加入，而不是藏在传输层。
- **查询串/`Range` 等端点级参数未实现**：路径不允许 `?`，需要它的 changes/内容卡再加显式编码入口；`with_header` 已支持 `Range` 之类的自定义头。
- **文档里的 workspace 成员清单仍是 S004 版本**：本卡只在 `interfaces.md` 末尾新增小节，没有重写旧清单行（避免与并行卡冲突）。
