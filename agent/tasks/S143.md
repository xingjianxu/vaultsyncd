# S143 — 对象区布局 `<vault_id>/<aa>/<hash>`、删除旧布局兼容、管理员默认名

状态：done；前置 S140/S142；依据 2026-11-08 用户决定（design §24 ADR-022）：可清空旧内部数据、重新部署并重建；同时优化对象区子目录名，并把管理员默认名改为服务运行用户、做成 NixOS 可配置项。

接口决定：

- `ObjectLayout` 只剩 `for_vault(objects_root, vault)`：规范相对路径 `<vault hex>/<fanout>/<hash>`，物理路径 `<state>/objects/<vault hex>/<fanout>/<hash>`，暂存 `<state>/objects/staging/<名字>`。删除 `ObjectLayout::new`、`legacy` 摘要集合、`SCOPED_PREFIX`、旧 `roots/...` 与全局 `objects/<aa>/<hash>` 兼容读取；`valid_storage_path` 只接受该 Vault 的规范路径。
- `apps/server/src/object_layout.rs` 改为纯计算 `layout(state_dir, vault)`，不再读数据库；`ExecutorContext::objects(vault)` / `ContentContext::objects(vault)` 同步改为同步方法，相关“布局登记不可读”失败分支随之删除。
- 备份/恢复/GC/Web 清单校验只认新布局；备份归档成员仍是 `objects/<VaultId>/<hash>`，清单 `storage_path` 必须是新规范相对路径。`apps/web/src/features/backup/archive.ts` 与 `apps/web/tests/backup.mjs` 同步。
- 数据库：`crates/server-store/migrations/0017_object_layout_vault_scoped.sql` 为语义围栏，schema 16→17；按用户决定本批清空内部状态并用新规则重建（Vault 工作目录内容保留、重新注册并采集），因此迁移不改行数据。
- 管理员：`vaultsyncd-admin init` 未给 `--login` 时默认取运行用户（`VAULTSYNCD_ADMIN_LOGIN` → `SUDO_USER` → `USER` → `LOGNAME` → `owner` 兜底）。NixOS 模块新增 `adminUser`（默认 `cfg.user`）与 `vaultsyncd-init` 包装命令；`rootPaths` 改名 `vaultPaths`，生成 `[vaults] allowed_bases`，preflight 输入同步为 `vaultPaths`（修正 S140 遗留的模块/preflight 不一致）。

验证（隔离树内实际执行）：

- `cargo test --locked --workspace` 全绿（server-core 325、server-store 99、server 12 等，含两 Vault 同摘要独立路径、旧布局拒绝、备份/恢复路径校验、迁移 14→15→16→17 与拒写）。
- `cargo fmt --all --check` 0；`cargo clippy --locked --workspace --all-targets -- -D warnings` 0。
- `cargo xwin check --locked --workspace --all-targets`（`nix develop .#windows`）0。
- `pnpm --recursive run typecheck` 0；`pnpm --recursive --if-present run test` 0（含更新后的 backup 清单校验）。

限制：

- 纯文档卡之外的部署由 S144 执行：主机 pin、`rootPaths`→`vaultPaths`、`adminUser`、清库、init(xingjian)、重新注册 Vault 与验收都在那里记录。
- 旧对象与旧备份不再兼容（ADR-022 明确接受）；`agent/tasks/S136*`、历史迁移与 `0015_root_scoped_objects.sql` 保持历史原名。
