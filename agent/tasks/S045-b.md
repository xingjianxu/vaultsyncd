## 2. 用例与实测返回码（`cargo test -p vaultsyncd-server --test uploads` → 6 passed）

| 用例 | 断言的真实结果 |
| --- | --- |
| `begin_put_part_and_status_report_real_parts_and_survive_reconnect` | `begin` 201（`part_count=3`、`chunk_size=4`）；块 0（4 B）、块 2（2 B）→ 200，`already_present=false`；`status` 报 `received=[(0,4),(2,2)]`（带块摘要）与 `missing=[(1,1)]`；块行确实是 `[0,2]`；**重连**（丢弃 app、数据库句柄与连接池，从同一批文件重新装配）后 `UploadStatus` 与重连前**完全相等** |
| `out_of_range_part_index_is_rejected_without_creating_a_part_row` | 块数 3、写索引 3 → **400 `INVALID_REQUEST`**（信息含“超出块数 3”、`retryable=false`）；块行为空、暂存目录为空、进度不变 |
| `oversized_payload_is_rejected_by_both_real_limits_and_leaves_nothing_behind` | 4 B 的块收到 64 B → **400 `INVALID_REQUEST`**（“长度应为 4，实际 64”）；默认块大小 **4 MiB 的块 → 200**（修复前会 413）；16 MiB + 2 → **413**（路由层，无错误信封）；两种情况都不产生块行、不留暂存文件，已收块进度只含真正收下的块 |
| `mismatched_part_digest_is_rejected_with_422_and_not_recorded` | 字节合法但声明摘要不符 → **422 `HASH_MISMATCH`**（信息含实测摘要）；不登记块、不写盘、进度不变 |
| `upload_from_another_login_session_is_404_and_does_not_touch_progress` | A 建会话并传块 0；B（同一 owner 的另一个登录会话）写块 1 与读进度都是 **404 `UNSUPPORTED_ENTRY`**；A 的进度仍是 `received=[0]`、`missing=[(1,2)]`，块行仍是 `[0]`，暂存只有 A 的那一块 |
| `missing_credentials_are_401_and_another_accounts_root_is_403` | 无凭据 `GET`/`PUT` → **401 `AUTH_EXPIRED`**；别人的 Root → **403 `ACCESS_DENIED`**（GET 与 PUT 都验），越权请求不写块行 |

种子方式沿用 `server-store` 的公开接口（`Database::open` + `users::insert_user` + `roots::insert_root`），
访问凭据走真实 `POST /v1/auth/login`（不手写会话行）。种子密码散列用 `PasswordHasher::with_params`
小参数只为省写入时间：登录校验读的是 PHC 文本里的参数，生产校验器不变。未给生产签名加测试专用入口。

## 4. 限制与后续

- **`x-part-sha256` 仍未进 `api/openapi.yaml`**（S045 §1 的已知缺口仍未闭合）：生成器
  `tools/xtask/src/generate/mod.rs` 的 `build_path_params` 明确拒绝非 `in: path` 参数。落实需要
  （S046 一并做，避免半途留下不一致契约）：① `Parameter.location` 接受 `header` 并要求
  `required: true`、值类型限 `string`；② `ApiOperation` 增 `header_params`，与路径占位符解耦；
  ③ `emit.rs` 的 `push_client_operation` 在签名里加头参数（如 `x-part-sha256` → `x_part_sha256`），
  并在 `request_headers(...)` 之后 `headers.set("x-part-sha256", …)`；④ `openapi.yaml` 的
  `putUploadPart.parameters` 声明该头；⑤ 重新生成 5 个文件并跑 `cargo xtask generate --check`、
  `pnpm --recursive run typecheck`、`cargo test -p vaultsyncd-xtask`。本卡判断代价中等（约 30—40 分钟
  且需前端 typecheck 证据），按父会话允许的范围留给 S046，未改动生成器与契约文件。
- **两个新错误码仍待 design 同步**（`INVALID_REQUEST`、`PART_CONFLICT`，见 S045 §1）：本卡未改
  `docs/design.md`，等用户确认措辞后由 design 卡补 §15.4 表行。
- 处理器里 `body.len() > max_chunk_size + 1` 的判断在路由层同值上限下不可达（防御性保留，不删）。
- 每 Root/每会话并发上传数上限、过期会话的暂存清理、`FsStaging` 在 async handler 内同步 I/O
  （块 ≤16 MiB，未 `spawn_blocking`）仍按 S045 §4 留待后续卡。
