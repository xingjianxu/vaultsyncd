# #3 执行小文件时延与常规规模性能基准（原 S106）

[GitHub Issue #3](https://github.com/xingjianxu/vaultsyncd/issues/3) · Task

- 分支：`issue-3-regular-scale-benchmark`（待领取时创建）
- Worktree：`/data/vaultsyncd-dev/worktrees/3-regular-scale-benchmark/`

## 交付目标

在三台独立 Windows 11 客户端与合规服务端环境下完成小文件时延与常规规模（1 万文件 / 约 10 GiB）真实性能基准，并给出带瓶颈分析的实测报告。

## 范围与接口

- 历史来源：[原 S106 交接](../../agent/tasks/S106.md)（仅完成宿主硬件与容量只读核查并写入 `docs/reports/performance.md`，尚未运行性能基准）。
- 代码与文档落点：`tools/bench/`、`docs/reports/performance.md`。

设计位置：[docs/design.md](../design.md) §20、T34。

直接前置：无（原前置 S101—S105 均已解除；当前阻塞于三台独立 Windows 客体、SSD 放置及 RTT 条件准备与真实采样工具）。

## 实施步骤

1. 核对固定候选版本，准备三台独立 Windows 11 设备（不得用单台客体顺序切换三身份替代）及合规 SSD/RTT 环境。
2. 在 `tools/bench/` 实现真实采样工具：先以小样本分段测量“稳定保存 → 服务端确认 → 另一客户端可见”各阶段耗时，再执行 1 万文件 / 约 10 GiB / 3 客户端常规档负载。
3. 记录硬件拓扑、网络 RTT、配置参数、各阶段 p95、RSS/CPU/队列深度与瓶颈分析；如需调参每次只改一个变量并保留对照。
4. 将完整实测数据、候选 SHA 与原始证据索引写入 `docs/reports/performance.md`，原始日志归档至 `/data/vaultsyncd-dev/runs/`。

## 验收条件

- [ ] 产出真实多端采样数据与瓶颈结论；仅在满足 `docs/design.md` §20 定义条件时判定 1—3 秒小文件时延目标达成。
- [ ] 全程无误报已同步、无未确认内容丢失、数据字节与哈希核对一致。
- [ ] 设备或环境未就绪时如实记录缺口与恢复条件，不下调目标或以单客体顺序运行替代通过。
