# 已知限制与首发缺口

2026-11-09：首发验收 **blocked**。状态与证据来源见[发布核对表](operations/release.md)；本页只维护当前影响，历史失败轨迹留在任务交接。

- **性能与正式容量未测**：S106 的 1 万文件/约10 GiB/3 客户端、S107 的10万文件/1 TiB/50 GiB/5 Windows设备均未完成；p95、RSS、CPU、队列与50 GiB重传字节没有结果。[报告](reports/performance.md)给出资源事实和预算。现有硬件有可规划容量，不把“客体/数据卷未准备”写成无法支持。
- **多机证据缺口**：S074/S101/S102 使用一台真实Windows客体上的隔离身份顺序运行；T02 的三台Windows要求不能据此标通过。当前缺少三台并发及五台容量拓扑。
- **当前代码与历史发行包不同源**：S101 的0.1.1包源为 `fcbbb93ecff408fedc8fbba6006c81b84a151727`；它不包含S102—S105修复。当前整合候选尚未完成同源全平台打包、安装与门禁，不能重标历史receipt。
- **签名与网络边界**：现存Windows包为unsigned-test；HTTPS验收使用开发私有CA/受限回环入口，不代表公网ACME或公网发布。Ubuntu amd64容器共享宿主内核，ARM64实测为完整系统TCG，不代表原生ARM性能。
- **Vault重新挂载**：S103确认mount id变化后保持VAULT_UNAVAILABLE、零删除；需要按准入恢复。不要以编辑在线数据库、忽略挂载身份或将空目录当删除解除暂停。步骤见[NixOS运维](operations/nixos.md)。
- **外部持续写入**：只承诺已稳定采集版本和最终稳定内容；无法保留每次未采集瞬态。历史/回收站默认30天，changes默认90天，不因容量不足静默缩短；同步不等于独立备份。
- **历史OS回调界限**：S011在该Windows构建下未取得CANCEL_FETCH_DATA触发证据；后续读取/断开/有界退出测试不自动补齐该观察。S012早期rename-over证据不足，后续S068/S103已有保存矩阵，不能把早期限制当作当前所有保存行为失败。
- **规格引用缺口**：S108卡引用的“附录B”在当前design不存在（仅附录A）；按§21、§25和真实交接完成索引，不臆造附录或改变验收要求。
